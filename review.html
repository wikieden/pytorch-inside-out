P01 · numpy 也能算 x @ w，PyTorch 多做了哪两件大事？

来源：第 1 章 · 加入 2026-11-05 · 复习记录：

答案
  1. GPU 计算：张量放到 GPU（.to("cuda") / Mac 上 .to("mps")），同一行代码自动走 GPU 版本；
  2. 自动求导（autograd）：前向时把"怎么算出来的"记在账本上，loss.backward() 照着倒推每个参数的梯度。

在这之上再有 nn、optim、DataLoader、distributed、torch.compile 等工具。

口诀：numpy 只会炒，PyTorch 开餐厅：多个厨房，一个记账员。

P02 · 一行 y = x @ w 在 PyTorch 里经过哪四站？分派器看什么？

来源：第 1 章 · 加入 2026-11-05 · 复习记录：

答案

① Python 前端（服务员）：接单，翻译成 C++； ② 分派器 Dispatcher（前台）：按张量身上的标签决定交给谁； ③ Autograd（记账员）：有输入要梯度时记一笔（grad_fn=<MmBackward0>），否则放行； ④ Kernel（厨房）：按设备选 CPU 或 GPU 实现真正去算。

分派器按顺序看标签：先 Autograd（记不记账），再看设备（第 3 章细讲：标签一直在，没人要梯度时记账员只是放行）。

口诀：服务员接单，前台看标签，记账员记一笔，厨房来下锅。

P03 · 一个 Tensor 里存了哪几样东西？x[i, j] 在 storage 里的位置怎么算？

来源：第 2 章 · 加入 2026-11-15 · 复习记录：

答案

storage（一排数）+ shape + stride（每维走一步跳几格）+ storage_offset + dtype + device（+ autograd 信息）。

位置 = offset + i × stride₀ + j × stride₁。

例：x = torch.arange(6).view(2, 3)，stride (3, 1)，x[1, 2] → 0 + 1×3 + 2×1 = 5。

口诀：一排数加说明书：shape 几行几列，stride 一步跳几格，offset 从哪开始。

P04 · view 和原张量是什么关系？为什么 x.t().view(6) 会报错，怎么办？

来源：第 2 章 · 加入 2026-11-15 · 复习记录：

答案

view 只改说明书（shape / stride / offset），和原张量共用 storage，改一个另一个也变。

x.t() 的 stride 是 (1, 3)，不是 shape (3, 2) 的标准 (2, 1)，不连续；按行读的顺序 0, 3, 1, 4, 2, 5 和 storage 顺序不同，光改说明书拉不成一行。

办法：x.t().reshape(6)（必要时复制）或 x.t().contiguous().view(6)，结果 [0, 3, 1, 4, 2, 5]。

口诀：view 只换说明书；转置跳着读不连续，view 不了就 reshape。

P05 · stride 为 0 是什么意思？expand 和 repeat 有什么区别？

来源：第 2 章 · 加入 2026-11-15 · 复习记录：

答案

stride 0：这一维走一步，内存一格不动，同一个数被"看"很多遍。

b.expand(4, 3)：stride (0, 1)，不复制；b.repeat(4, 1)：真复制出 12 个数，stride (3, 1)。广播就是靠 stride 0。

口诀：stride 为 0 一份当多份；expand 假复制，repeat 真复制。

P06 · dispatch key（标签）的处理顺序是什么？redispatch 是什么？

来源：第 3 章 · 加入 2026-11-15 · 复习记录：

答案

简化梯子：Autocast → Autograd → ADInplaceOrView →（Python，张量子类）→ 后端（CPU / CUDA / MPS / Meta）。

每一层做完自己的事，把自己的标签从"待处理"里去掉，再叫一次分派器（redispatch），活就落到下一层。

例：autocast 里 x @ w：先转 bf16（转换也被记账：ToCopyBackward0），再记 MmBackward0，最后 CPU 用 bf16 算。

口诀：先混合精度，再记账，再版本登记，最后进厨房；每层干完撕标签。

P07 · 不要梯度的普通张量身上有没有 Autograd 标签？inference_mode 里新建的张量呢？

来源：第 3 章 · 加入 2026-11-15 · 复习记录：

答案

普通 CPU / GPU 张量一直有 Autograd 标签：DispatchKeySet(CPU, ADInplaceOrView, AutogradCPU, AutocastCPU)；记账员每次都被叫到，没有输入要梯度就放行。

inference_mode 里新建的张量没有 Autograd（和 ADInplaceOrView）标签：DispatchKeySet(CPU, AutocastCPU)，连"看一眼"都省了；代价是之后不能参与要求导的计算。

口诀：标签一直在，没人要就放行；inference_mode 把记账员整个拿掉。

P08 · Meta 设备是什么？举两个用处。

来源：第 3 章 · 加入 2026-11-15 · 复习记录：

答案

Meta 设备的"厨房"只算输出形状、不分配内存也不算数。torch.empty(10**6, 10**6, device="meta") 名义 4 TB，m @ m.T 瞬间返回形状 (10⁶, 10⁶)。

用处：① torch.compile / torch.export 抓图时推形状（fake tensor 同理）；② 大模型先 with torch.device("meta"): 建结构，再按分片真正分配（FSDP2、load_state_dict(assign=True)）。

口诀：Meta 只算形状不算数。

P09 · z = w·x + b，L = z²，x = 2、w = 3、b = 1。∂L/∂w、∂L/∂b 各是多少？怎么来的？

来源：第 4 章 · 加入 2026-11-15 · 复习记录：

答案

z = 7，L = 49。链式法则：∂L/∂z = 2z = 14；∂z/∂w = x = 2，∂z/∂b = 1。

∂L/∂w = 14 × 2 = 28；∂L/∂b = 14 × 1 = 14。

口诀：链式法则把每一小步的放大倍数乘起来。

P10 · 计算图（账本）是怎么建的、backward 怎么走？哪些张量有 .grad？

来源：第 4 章 · 加入 2026-11-15 · 复习记录：

答案

前向时每个可导运算记一个节点（PowBackward0、AddBackward0、MulBackward0…），用 next_functions 连成 DAG；每次前向重建（define-by-run），所以 Python 的 if / for 随便写。

backward() 从 loss 出发倒着走，每个节点把上游梯度乘上本步的放大倍数往下传，最后由 AccumulateGrad 加进叶子张量（自己创建的，如 w、b）的 .grad。中间结果（如 z）不是叶子，.grad 为 None。

口诀：前向记节点，反向倒着走，结果存叶子。

P11 · 为什么每步要 zero_grad？原地修改为什么会让 backward 报错？

来源：第 4 章 · 加入 2026-11-15 · 复习记录：

答案

.grad 是累加的：同一个图再反向一次，28 变 56。不清零就会把上一步的梯度叠上来（故意不清零就是梯度累积）。

反向要用前向时的值（如 exp 的反向用它的输出）。每个张量有版本号，原地修改 +1；记账时存下版本号，反向时对不上就报 modified by an inplace operation。改成 a = a + 1 就行。

口诀：.grad 只会加，每步要清零；反向要用的数别原地改。

P12 · 怎么用 torch.autograd.Function 自定义反向？怎么检查写对了？

来源：第 4 章 · 加入 2026-11-15 · 复习记录：

答案

继承 torch.autograd.Function，写两个静态方法： - forward(ctx, x)：算结果，ctx.save_for_backward(...) 存反向要用的东西； - backward(ctx, grad_out)：返回"上游梯度 × 本步放大倍数"，每个输入一个。

例：ReLU 的反向 grad_out * (x > 0)，输入 [−1, 2, 3] 得梯度 [0, 1, 1]。

检查：torch.autograd.gradcheck（用 float64），和数值导数对拍。

口诀：forward 存 ctx，backward 返回上游梯度乘本步倍数；gradcheck 用 float64。

P13 · 为什么不加同步直接掐表测不准 GPU 运算？怎么测才对？

来源：第 5 章 · 加入 2026-11-15 · 复习记录：

答案

GPU 运算是异步的：CPU 把 kernel 挂进队列就返回。本机 MPS 实测 4096 矩阵乘：下单 0.15 ms，真正做完 10.2 ms。

正确：计时前后 torch.cuda.synchronize()（Mac 上 torch.mps.synchronize()）或用 torch.cuda.Event；先热身；或直接用 torch.utils.benchmark / triton.testing.do_bench。

口诀：CPU 挂单就走，GPU 排队慢做；掐表之前先同步。

P14 · 举出至少五种同步点。同步点为什么伤性能？

来源：第 5 章 · 加入 2026-11-15 · 复习记录：

答案

.item()、.tolist()、float(t)、print(t)、.cpu() / .numpy()、依赖张量值的 Python if、nonzero / unique / 布尔索引（输出大小看数据）、torch.cuda.synchronize()。

伤性能：CPU 要等 GPU 队列清空才拿到数，之后才给下一步下单，GPU 就会空等一段；每步都有的话时间线上全是空隙。

口诀：拿数回来就要等，item、print、if 都是坎。

P15 · stream 是什么？跨 stream 用数据要注意什么？non_blocking 拷贝要配合什么？

来源：第 5 章 · 加入 2026-11-15 · 复习记录：

答案

一条 stream 是一条队列：同一条按顺序执行，不同条可以并行（如一边算这批、一边拷下一批；NCCL 通信也在单独 stream）。

跨 stream 用数据前必须等：wait_stream 或 Event，否则可能读到没拷完的数。

.to(dev, non_blocking=True) 要配 pinned memory（锁页内存），DataLoader 的 pin_memory=True 就是干这个。

口诀：一条 stream 一条队，跨队用数先等待；non_blocking 配锁页内存。

P16 · memory_allocated 和 memory_reserved 有什么区别？为什么 nvidia-smi 显示的比张量实际用的多？

来源：第 5 章 · 加入 2026-11-15 · 复习记录：

答案

PyTorch 有缓存分配器：张量释放后显存不还给驱动，留着复用（cudaMalloc 慢）。 - memory_allocated：张量真正在用的； - memory_reserved：从驱动借来的总量（nvidia-smi 看到的接近这个）。

差额不是泄漏。本机 MPS 实测：del 一个 64 MB 张量后"在用"从 128 降到 64 MB，"借来"仍约 1 GB。碎片多时设 PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True。

口诀：显存仓库借了不还，在用和借来是两个数。

P17 · eager 模式的两笔主要开销是什么？

来源：第 6 章 · 加入 2026-11-15 · 复习记录：

答案

① 每个算子都要过一遍 Python 和分派器（几微秒），小算子时下单比计算还贵； ② 不会合并：(x.sin().cos() * 2).sum(-1) 是 4 个 kernel，中间结果 t1、t2、t3 每个都写进显存再读出来，逐元素运算的时间几乎都花在这些读写上。

口诀：eager 一步一单一趟显存。

P18 · torch.compile 的三道工序是什么？guards 是什么？

来源：第 6 章 · 加入 2026-11-15 · 复习记录：

答案

① TorchDynamo：旁听 Python 字节码，把张量运算抄成 FX 图，记下 guards；② AOTAutograd：提前生成反向图，前向 + 反向一起优化（还会 functionalize 去掉原地修改）；③ TorchInductor：融合并生成代码（GPU 上 Triton，CPU 上 C++）。

guards：这份编好的代码适用条件（形状、dtype、设备…）的检查清单，下次调用全对就直接复用。

实测：sin → cos → ×2 → sum 融成一个 cpp_fused_cos_mul_sin_sum_0。

口诀：Dynamo 抄图，AOTAutograd 配反向，Inductor 融合写代码。

P19 · 什么是 graph break（断图）？常见原因和改法？怎么查？

来源：第 6 章 · 加入 2026-11-15 · 复习记录：

答案

Dynamo 抄不下去时把图切断，回 Python 执行再接着抄。代价：两段之间不能融合、可能同步。

原因 → 改法：依赖张量值的 if / while → torch.where；print / .item() → 挪出去；不认识的库 → torch.library 注册成算子；输出大小依赖数据 → 固定形状 + mask。

查：torch._dynamo.explain(f)(x)（实测带 if 的函数 graph_count 2、break 1）、TORCH_LOGS=graph_breaks、fullgraph=True 让断图直接报错。

口诀：看张量的值走分支就断图，用 where 改。

P20 · 什么时候会重编译？mode 的三个选项各适合什么？

来源：第 6 章 · 加入 2026-11-15 · 复习记录：

答案

guards 不通过就重编译：形状变、dtype 变、train/eval 切换、读了会变的全局变量。实测长度 4 → 8 重编译一次，第二次编成动态形状，16 就直接复用。

default：融合 + 生成代码；reduce-overhead：再套 CUDA Graph，适合小 batch、推理 decode；max-autotune：对 matmul 等试多种实现挑最快，编译更久。

口诀：guards 不过就重编，形状在变编成动态。

P21 · nn.Module 会自动登记哪些东西？哪两种写法不会被登记？

来源：第 7 章 · 加入 2026-11-15 · 复习记录：

答案

赋给 self 的子模块、nn.Parameter、register_buffer 的 buffer 会登记。

不登记：普通 Python list 里的层（要用 nn.ModuleList）、普通张量属性（不会跟着 .to(device)）。普通 list 不报错，只是那几层不进 parameters()、训练时不更新。

nn.Linear(4, 8) 的权重形状是 (8, 4)：输出维在前，参数 4×8 + 8 = 40。

口诀：赋给 self 自动登记；普通 list 不登记，要用 ModuleList。

P22 · state_dict 是什么？名字是怎么来的？

来源：第 7 章 · 加入 2026-11-15 · 复习记录：

答案

"名字 → 张量"的清单，包含所有参数和 buffer。名字（FQN）就是在模块树上的路径，如 fc1.weight、layers.3.attn.q_proj.weight。

.to()、parameters()、zero_grad()、apply(fn)、requires_grad_(False) 都是沿这棵树递归。

口诀：模块成树、路径成名，state_dict 是名字到张量的清单。

P23 · model.eval() 改变了什么、没改变什么？Dropout 训练时为什么要放大？

来源：第 7 章 · 加入 2026-11-15 · 复习记录：

答案

eval 递归把 training 设为 False：Dropout 不再丢、BatchNorm 用存下的统计量。它不关记账，推理还要 torch.inference_mode()。

Dropout 训练时以概率 p 清零，留下的乘 1/(1−p)，使期望不变（p = 0.5 时留下的变成 2）；推理时直接用原值。

口诀：train/eval 切层的行为，不管梯度；推理 eval 加 inference_mode。

P24 · DataLoader 内部的三步是什么？10 个样本、batch_size 4 会得到几批？

来源：第 8 章 · 加入 2026-11-15 · 复习记录：

答案

① sampler 出下标（shuffle 时打乱）；② 对每个下标调 ds[i]；③ collate 把一组样本拼成张量（默认 torch.stack）。

10 个样本、每批 4：[4, 4, 2] 三批；drop_last=True 扔掉不满的，剩 2 批。

口诀：Dataset 管第 i 个是什么，DataLoader 管打乱分批拼盘。

P25 · num_workers 至少要多少 GPU 才不等数据？相关的几个参数各干什么？

来源：第 8 章 · 加入 2026-11-15 · 复习记录：

答案

worker 数 ≥ 读一批的时间 ÷ 训一步的时间。例：读 40 ms、训 25 ms → 至少 2 个；0 个时每步 65 ms，GPU 忙 38%。

prefetch_factor 每个 worker 提前备几批；persistent_workers=True epoch 间不关进程；pin_memory=True 放进锁页内存，配 .to(..., non_blocking=True)。

口诀：worker 数 ≥ 读一批 ÷ 训一步。

P26 · 样本长短不一时 DataLoader 为什么报错、怎么办？多卡时数据怎么分？

来源：第 8 章 · 加入 2026-11-15 · 复习记录：

答案

默认 collate 用 torch.stack，要求形状一样。自己写 collate_fn：pad_sequence(..., batch_first=True) 补齐，并返回 mask 标出真数据；或像 LLM 预训练那样拼接后切成定长。

多卡用 DistributedSampler，按 rank 隔着分下标；每个 epoch 开始前 sampler.set_epoch(epoch)。

map-style（__getitem__，能随机取）vs iterable-style（__iter__，只能顺序读）。

口诀：长短不齐补齐加 mask；多卡 DistributedSampler，每轮 set_epoch。

P27 · 训练循环的五行主干是什么？zero_grad 能放在哪？

来源：第 9 章 · 加入 2026-11-15 · 复习记录：

答案

pred = model(x) → loss = loss_fn(pred, y) → opt.zero_grad() → loss.backward() → opt.step()。

zero_grad 只要在 backward 之前（或上一步 step 之后）就行；不能夹在 backward 和 step 之间（刚算的梯度会被清掉）。

口诀：前向、loss、清梯度、反向、更新。

P28 · autocast 混合精度怎么写？参数和优化器用什么精度？什么时候要 GradScaler？

来源：第 9 章 · 加入 2026-11-15 · 复习记录：

答案

with torch.autocast(device_type, dtype=torch.bfloat16): 包住前向和 loss，backward 放在外面。矩阵乘走 bf16，求和、softmax、loss 等敏感运算留 float32（由 Autocast 层的名单决定）。

参数本身和优化器更新仍是 float32。fp16 才需要 GradScaler（防梯度下溢），bf16 不需要。

口诀：autocast 包前向，矩阵走 bf16；参数和更新仍是 fp32。

P29 · clip_grad_norm_ 做了什么？梯度 [3, 4]、上限 1 时结果是什么？放在哪？

来源：第 9 章 · 加入 2026-11-15 · 复习记录：

答案

把所有参数梯度拼成一个向量，长度超过上限就等比例缩小，方向不变。[3, 4] 长度 5，缩 5 倍 → [0.6, 0.8]，函数返回裁剪前的范数 5（值得记日志）。

放在 backward 之后、step 之前。

口诀：裁剪放在反向和更新之间，方向不变只缩长。

P30 · warmup + cosine 学习率怎么算？最大 3e-4、warmup 100、总 1000 步时第 50 / 100 / 550 / 1000 步各多少？

来源：第 9 章 · 加入 2026-11-15 · 复习记录：

答案

t < W：η = η_max · t / W；之后 η = η_max/2 · (1 + cos(π(t − W)/(T − W)))。

第 50 步 1.5e-4，第 100 步 3e-4，第 550 步（衰减段正中）1.5e-4，第 1000 步 0。LambdaLR 的函数返回"最大值的几倍"；sched.step() 放在 opt.step() 之后。

口诀：学习率先升后余弦降，调度跟在更新后。

P43 · 为什么直接算 log(Σ eˣ) 会得到 inf？logsumexp 怎么躲过去？

来源：第 13 章 · 加入 2026-11-15 · 复习记录：

答案

e¹⁰⁰⁰ 超出 float32 上限（约 3.4 × 10³⁸）→ inf。

恒等式：log Σ eˣⁱ = M + log Σ e^(xᵢ − M)，M 取最大值。减完最大项是 e⁰ = 1，其余 ≤ 1，不会爆。例 [1000, 1001, 1002]：M = 1002，e^(−2) + e^(−1) + 1 = 1.503，log 1.503 = 0.4076，结果 1002.4076。softmax 内部也先减最大值。

口诀：logsumexp 先减最大，exp 就不爆。

P52 · 写出 AdamW 一步的公式。θ = 1、g = 0.5、lr = 0.1、wd = 0.01 第一步后 θ 是多少？

来源：第 15 章 · 加入 2026-11-15 · 复习记录：

答案

θ ← θ − η·λ·θ（先衰减）；m ← β₁m + (1−β₁)g，v ← β₂v + (1−β₂)g²；m̂ = m/(1−β₁ᵗ)，v̂ = v/(1−β₂ᵗ)；θ ← θ − η·m̂/(√v̂ + ε)。

衰减后 0.999；m = 0.05、v = 0.00025、m̂ = 0.5、v̂ = 0.25；更新量 0.1 → θ = 0.899。

第一步更新量 m̂/√v̂ = g/|g| = 1，和梯度大小无关（梯度 0.0005 也走 0.1）。

口诀：AdamW 先衰减，再用惯性除以平时梯度，首步约等学习率。

P53 · 优化器的 for-loop / foreach / fused 三种实现有什么区别？哪些参数通常不做 weight decay？

P58 · all_reduce、all_gather、reduce_scatter、broadcast 各是什么结果？

来源：第 17 章 · 加入 2026-11-15 · 复习记录：

答案

all_reduce：大家求和，人人拿到总和（[1, 2] + [2, 4] → 两人都是 [3, 6]）； all_gather：拼起来，人人一份完整的； reduce_scatter：求和后每人只拿一段（[10, 20] + [20, 40] → rank 0 [30]、rank 1 [60]）； broadcast：一个人的数复制给所有人。 另有 all_to_all（每人切 N 份分发，MoE 用）、barrier（只同步）。

口诀：all_reduce 加起来人人有，all_gather 拼起来人人有，reduce_scatter 加完各拿一段。

P59 · all_reduce 和 reduce_scatter、all_gather 是什么关系？集合通信有什么铁律？

来源：第 17 章 · 加入 2026-11-15 · 复习记录：

答案

all_reduce = reduce_scatter + all_gather：先每人拿到一段完整的和，再把各段拼回去。ZeRO / FSDP 就是在两半中间插进"只更新自己那一段"。

铁律：所有进程都要调用、按同样的顺序调用，否则其他 rank 永远等，程序卡死。

口诀：大家同序调用，少一个就卡死；all_reduce 拆成两半。

P60 · ring all-reduce 每张卡要发送多少数据？各种并行主要用哪个集合通信？

来源：第 17 章 · 加入 2026-11-15 · 复习记录：

答案

每卡发 2(N − 1)·K/N ≈ 2K（K = 元素数），几乎不随卡数增长：4 卡 1.5K，64 卡 1.97K。reduce_scatter、all_gather 各约 K。

DDP：all_reduce 梯度；FSDP：all_gather 参数 + reduce_scatter 梯度；TP：层内 all_reduce；PP：send / recv；EP：all_to_all；初始化：broadcast。

口诀：ring 每卡发两倍 K，几乎不随卡数涨。

P61 · DDP 在包装时、反向时、更新时各做了什么？

来源：第 18 章 · 加入 2026-11-15 · 复习记录：

答案

包装时：broadcast rank 0 的参数，保证起点一致（实测两个 rank 不同种子初始化，包装后相同）。 反向时：梯度按桶 all_reduce 并除以 N 取平均（实测 [1, 0] 与 [0, 1] → 都是 [0.5, 0.5]）。 更新时：不通信，各自 step，参数自然一致。

口诀：包装时广播参数，反向时 all_reduce 取平均，更新各自做。

P62 · DDP 的"分桶 + 重叠"是怎么把通信藏起来的？桶大小怎么取舍？

来源：第 18 章 · 加入 2026-11-15 · 复习记录：

答案

反向从最后一层往前算，最后几层梯度最先好。参数按反向顺序装进桶（默认 25 MB），一桶凑齐就 all_reduce，和前面几层的反向并行（靠参数上的 hook 触发）。例：4 段各 10 ms、每桶 8 ms：算完再发 72 ms，重叠后约 48 ms，只剩最后一桶露在外面。

桶太小：通信次数多、启动开销大；桶太大：第一桶要等很久才发，重叠少（bucket_cap_mb）。

口诀：梯度好一桶发一桶，通信藏在计算后。

P63 · DDP 梯度累积为什么要 no_sync？有参数没进 loss 会怎样？

来源：第 18 章 · 加入 2026-11-15 · 复习记录：

口诀：累积前几步 no_sync，参数没进 loss 要报错。

P66 · FSDP2 里一层的生命周期是怎样的？为什么必须逐层 fully_shard？

来源：第 19 章 · 加入 2026-11-15 · 复习记录：

答案

P67 · reshard_after_forward、MixedPrecisionPolicy、HSDP 各是什么？

来源：第 19 章 · 加入 2026-11-15 · 复习记录：

答案

P69 · DTensor 的三种 placement 是什么？换 placement 对应哪些集合通信？

来源：第 20 章 · 加入 2026-11-15 · 复习记录：

答案

Shard(d)：沿第 d 维切开；Replicate()：每卡一份完整；Partial()：每卡一份部分和。

Shard → Replicate = all_gather；Partial → Replicate = all_reduce；Partial → Shard = reduce_scatter。实测 (dt * 2).sum() 的 placement 是 Partial(sum)，full_tensor() 才 all_reduce 得 56。

口诀：Shard 切开、Replicate 复制、Partial 部分和，换摆法就是通信。

P70 · 张量并行怎么切 MLP？为什么只需要一次 all_reduce？

来源：第 20 章 · 加入 2026-11-15 · 复习记录：

答案

W₁ 按列切（Colwise）：每卡算出中间结果的一半列，逐元素激活各算各的，不通信；W₂ 按行切（Rowwise）：正好对上自己那一半，每卡得到一个和最终结果同形状的部分和；最后 all_reduce 一次。例 X = [1, 2]：两卡部分和都是 [1, 2]，相加 [2, 4]，和不切一样。

parallelize_module(m, mesh, {"w1": ColwiseParallel(), "w2": RowwiseParallel()})；nn.Linear 存转置权重，所以 Colwise 显示为 Shard(0)、Rowwise 为 Shard(1)。

口诀：TP 先列后行，中间不传、最后一次 all_reduce。

P71 · TP 为什么只在一台机器内用？SP（序列并行）补了什么？

来源：第 20 章 · 加入 2026-11-15 · 复习记录：

答案

TP 每层前向 2 次、反向 2 次 all_reduce，而且下一步要等它的结果，难以和计算重叠，需要 NVLink 这样的高带宽，一般 TP ≤ 8、只在机内。

SP：把 LayerNorm、dropout 部分的激活沿序列维切开，all_reduce 换成 reduce_scatter + all_gather，通信量不变、激活显存更省（SequenceParallel()）。

口诀：TP 只在机内用，SP 再把 norm 按序列切。

P73 · AFAB 和 1F1B 调度有什么区别？还有哪些进一步的办法？

来源：第 21 章 · 加入 2026-11-15 · 复习记录：

答案

口诀：1F1B 前反交替，激活不随 m 涨。

P74 · 上下文并行（CP）怎么处理 attention？因果 mask 下为什么要 zig-zag？

来源：第 21 章 · 加入 2026-11-15 · 复习记录：

P92 · fp16 训练为什么需要 GradScaler？它怎么工作？bf16 为什么不用？

来源：第 26 章 · 加入 2026-11-15 · 复习记录：

答案

fp16 范围小：上溢（> 65504 变 inf）、下溢（小梯度变 0，实测 1e−8 转 fp16 = 0）。

GradScaler：loss 乘大数（如 65536）→ 梯度跟着放大躲开下溢（实测 1e−8 × 65536 转 fp16 = 0.00066）→ 更新前除回来；出现 inf 就跳过这步并调小倍数。写法：scale(loss).backward() → unscale_(opt) → 裁剪 → step → update。

bf16 指数位和 fp32 一样，范围够，不需要。

口诀：fp16 梯度会下溢，GradScaler 先放大再除回。

P93 · TF32 是什么？怎么打开？能快多少？

来源：第 26 章 · 加入 2026-11-15 · 复习记录：

答案

Ampere 以后张量核心上的格式：fp32 输入在乘法时只保留 10 位尾数、8 位指数，累加仍 fp32。torch.set_float32_matmul_precision("high") 打开（默认 "highest" 是真 fp32）。H100 上 fp32 约 67 TFLOPS，TF32 约 494 TFLOPS（稠密），约 7 倍，对训练几乎没影响。

口诀：fp32 一行开 TF32。

P94 · FP8 训练难在哪？怎么解决？惯例是怎么分配格式的？

来源：第 26 章 · 加入 2026-11-15 · 复习记录：

答案

E4M3 最大 448、间隔粗，大了溢出、小了丢失。靠缩放系数：per-tensor → 细粒度块（DeepSeek-V3：激活 1 × 128、权重 128 × 128 一个系数，离群值只影响一块）→ MX 格式（每 32 个数共享指数，Blackwell 原生）。

口诀：FP8 再快一倍，靠缩放系数，粒度越细越稳。

P95 · 训练显存由哪几块组成？为什么长序列时激活常比参数还大？

来源：第 27 章 · 加入 2026-11-15 · 复习记录：

答案

模型状态（混合精度 AdamW 约 16Ψ）、激活（为反向存下的中间结果，随 b·s·h·L 增长）、临时缓冲、碎片。

口诀：显存四块：模型状态十六 Ψ、激活随 b s h L、临时和碎片。

P96 · 激活重计算（checkpoint）怎么省显存？代价多大？什么是选择性重计算？

来源：第 27 章 · 加入 2026-11-15 · 复习记录：

答案

checkpoint(block, h, use_reentrant=False)：前向只存每块的输入，反向时把这块的前向再跑一遍拿到中间结果。实测 8 个 MLP 块：存下的激活 9.125 MB → 1.125 MB。

代价：多一次前向，总计算从 3F 变 4F，多约 1/3。选择性重计算只重算"大但便宜"的（如 softmax 输出），矩阵乘输出照样存；FlashAttention 本身就在反向里重算分数表。

口诀：重计算只存每块输入，反向再跑一遍前向，多三分之一算力。

P97 · OOM 时怎么看清显存被谁占了？正常的显存曲线长什么样？

P98 · OOM 了按什么顺序去省显存？

来源：第 27 章 · 加入 2026-11-15 · 复习记录：

答案

P99 · 40 个小算子的函数，eager 和 compile 实测差多少？省在哪？

P100 · 训练里 compile 套在哪一层？怎么避免重编译？

来源：第 28 章 · 加入 2026-11-15 · 复习记录：

答案

大模型常用区域编译：每个 Transformer 块单独 compile()，结构相同的块只编一次、全部复用，冷启动快很多（块之间不能融合）。也可以单独编 loss / 优化器。

P101 · CUDA Graph 是什么？怎么用？有哪些限制？

来源：第 28 章 · 加入 2026-11-15 · 复习记录：

答案

把一串 kernel 录成一张图，之后一次 launch 重放。手动：g = torch.cuda.CUDAGraph()，热身后 with torch.cuda.graph(g): static_y = model(static_x)；每次 static_x.copy_(batch)、g.replay()、从 static_y 读。

限制：形状固定；输入输出地址固定；图里不能有同步点和 CPU 逻辑；录的时候不能新分配显存；随机数要特殊处理。省事的办法：torch.compile(mode="reduce-overhead")。

口诀：CUDA Graph 录一次套餐号，形状地址要固定、不能同步和新分配。

P102 · 什么场景值得上 CUDA Graph？怎么从时间线上判断？

P103 · roofline 模型：一个 kernel 的时间下限怎么算？什么是算术强度和拐点？

来源：第 29 章 · 加入 2026-11-15 · 复习记录：

答案

t ≥ max(运算次数 / 峰值算力, 读写字节 / 带宽)。算术强度 I = FLOPs / 字节；拐点 = 峰值 / 带宽（H100 约 989 TFLOPS / 3.35 TB/s ≈ 295；本机 Mac GPU 约 29）。I 低于拐点是访存受限，高于是算力受限。

口诀：时间看两笔，谁大谁是瓶颈；强度低于拐点就是访存受限。

P104 · 常见算子的算术强度大约多少？哪些是访存受限？

来源：第 29 章 · 加入 2026-11-15 · 复习记录：

答案

fp32 x + y：1 次运算 / 12 字节 ≈ 0.08；GELU ≈ 1；LayerNorm / softmax ≈ 1–2：都远低于拐点，访存受限。bf16 n × n 矩阵乘 ≈ n/3（n = 4096 时 1365），算力受限。

结论：Transformer 里除了矩阵乘，几乎所有算子（偏置、激活、残差、norm、softmax、dropout、RoPE）时间只看读写字节数。

口诀：矩阵乘吃算力，其余算子吃带宽。

P105 · 融合为什么能变快？本章 MPS 实测的数字是什么？

来源：第 29 章 · 加入 2026-11-15 · 复习记录：

答案

融合让中间结果不落显存，读写字节变少。gelu(x + b) * s（2²⁴ 个 float）：eager 3 个 kernel 读写 8 个张量 537 MB、1.14 ms；compile 1 个 kernel 读写 4 个张量 268 MB、0.57 ms。两者有效带宽都约 471 GB/s——带宽不变、字节减半、时间减半。fused AdamW、FlashAttention、融合 CE 同一个原理。

口诀：融合不让中间结果落显存，带宽不变字节减半时间减半。

P106 · 要不要手写一个融合 kernel，按什么步骤判断？

来源：第 29 章 · 加入 2026-11-15 · 复习记录：

答案

1 profiler 里占比多少（< 5% 别管）→ 2 是不是访存受限 → 3 compile 是不是已经融了（看生成代码）→ 4 离理论最快差多少：理论最快 = 必须读写字节 ÷ 带宽 → 5 差得多又 compile 融不了（特殊规约、在线 softmax、反量化 + matmul）才手写 Triton。

例：(8192, 4096) bf16 LayerNorm 必须读写 128 MiB，H100 理论约 40 µs；实测 150 µs 值得优化，50 µs 就别折腾。

口诀：手写之前先算离理论最快还差多少。

P107 · 推理时 eval、no_grad、inference_mode 各关掉了什么？什么时候只能用 no_grad？

来源：第 30 章 · 加入 2026-11-15 · 复习记录：

答案

eval：切换 Dropout / BN 行为；no_grad：不记账；inference_mode：no_grad 的全部，再加上新张量不带 Autograd 标签、不记版本号，更快。

inference_mode 里的张量之后不能参与要求导的计算（实测报 Inference tensors cannot be saved for backward）；推理结果还要拿去训练（如 RL 采样后算 loss）时用 no_grad。

口诀：推理开 eval 加 inference_mode。

P108 · KV cache 是什么原理？不带 cache 生成 T 个 token 要算多少次 token？

来源：第 30 章 · 加入 2026-11-15 · 复习记录：

答案

因果 attention 里前面的 token 看不到后面的，所以旧 token 的 K、V 每一步都一样。每层把 K、V 存下来，新 token 只算自己的 q、k、v，q 和整个 cache 做 attention（实测和一次性因果 attention 结果一致）。

不带 cache：第 t 步重算 t 个，累计 T(T + 1)/2，O(T²)；带 cache：T 次。

口诀：因果 attention 旧 KV 不变，存进 cache 每步只算新 token。

P109 · KV cache 每个 token 占多少？Llama-2-7B 呢？GQA 怎么省？

来源：第 30 章 · 加入 2026-11-15 · 复习记录：

答案

每 token = 2 × 层数 × KV 头数 × 每头维度 × 每数字节。Llama-2-7B（32 层、32 头、128 维、fp16）：2 × 32 × 32 × 128 × 2 = 524288 字节 = 0.5 MB，4096 token 一条就 2 GiB。

GQA（分组查询注意力）：几个 q 头共用一组 K、V 头。Llama-3-8B 只有 8 个 KV 头，每 token 128 KB，是 1/4。

口诀：每 token cache 是 2 乘层乘 KV 头乘头维乘字节，GQA 共享省几倍。

P110 · prefill 和 decode 有什么不同？batch 1 decode 的速度上限怎么算？

来源：第 30 章 · 加入 2026-11-15 · 复习记录：

答案

prefill 一次处理整段提示词，矩阵乘大，算力受限；decode 每次 1 个 token，每生成一个 token 都要把全部权重读一遍，访存受限。

上限 ≈ 带宽 ÷ 权重字节：7B bf16（14 GB）在 H100（3.35 TB/s）上约 240 tok/s。提速方向：量化减少字节、增大 batch 一次读多次用、CUDA Graph 去 launch 开销。

口诀：prefill 吃算力、decode 吃带宽，上限是带宽除以权重字节。

P111 · 为什么普通 KV cache 不能录 CUDA Graph？静态 cache 怎么做？

来源：第 30 章 · 加入 2026-11-15 · 复习记录：

答案

普通写法每步 torch.cat 变长、新分配显存，形状和地址都在变。静态 cache：一开始按最大长度预分配 (B, H, T_max, d)，每步按下标把新 k、v 写进第 t 个位置，attention 用 mask 只看前 t 个；形状地址不变，整个 decode 一步用 torch.compile(mode="reduce-overhead") 录成 CUDA Graph（gpt-fast 的做法；HF 的 cache_implementation="static"）。

口诀：静态 cache 才能录 CUDA Graph。

P116 · Triton 写 kernel 和 CUDA C++ 写 kernel 最大的思路差别是什么？

来源：第 32 章 · 加入 2026-11-15 · 复习记录：

答案

CUDA（SIMT）写一个线程的代码，自己管线程编号、warp、共享内存、同步。Triton（块级 SPMD）写一个 program 的代码，一次处理一整块数据（像 numpy 一样整块运算），块内线程怎么分工、共享内存、合并访存交给编译器。一个 program 大致对应一个线程块。

口诀：CUDA 写一个线程，Triton 写一个 program 管一块。

P117 · Triton kernel 的五个零件是什么？n = 2500、BLOCK = 1024 时 grid 和最后一个 program 是什么情况？

P118 · 行规约（softmax、norm）在 Triton 里怎么组织？softmax 的越界位置为什么补 −∞？

来源：第 32 章 · 加入 2026-11-15 · 复习记录：

答案

一个 program 处理一整行，grid = 行数；BLOCK ≥ 行长取 2 的幂；块内 tl.max、tl.sum 规约，一行读一次写一次。

越界位置补规约的"中性值"：softmax 补 −∞，因为 exp(−∞) = 0 不影响求和；若补 0，exp(0) = 1 会把分母弄错。求和补 0、求最大补 −∞。

口诀：行规约一行一个 program，越界补不影响结果的值。

P120 · 自己写的 kernel 直接包成 Python 函数调用，有什么问题？

来源：第 33 章 · 加入 2026-11-15 · 复习记录：

P121 · torch.library.custom_op 怎么写？register_fake 是干什么的？

来源：第 33 章 · 加入 2026-11-15 · 复习记录：

答案

P122 · register_autograd 怎么写？本章 add_relu 的梯度是多少？

来源：第 33 章 · 加入 2026-11-15 · 复习记录：

答案

op.register_autograd(backward, setup_context=setup_context)：setup_context(ctx, inputs, output) 存反向要用的东西；backward(ctx, grad) 对每个输入返回一个梯度。

add_relu(x, y)：x = [−2, 1, 3]、y = [1, −3, 1] → 输出 [0, 0, 4]；反向 grad * (out > 0)，两个输入的梯度都是 [0, 0, 1]（加法对两边倍数都是 1）。挂在注册过的算子上，compile 也能正确处理反向。

口诀：register_autograd 存东西给梯度。

P123 · opcheck 检查什么？它能保证数值正确吗？Triton kernel 为什么用 triton_op？

来源：第 33 章 · 加入 2026-11-15 · 复习记录：

P124 · 什么时候需要写 C++ / CUDA 扩展，而不是 compile 或 Triton？

P125 · C++ 扩展的三段是什么？和分派表的行、列怎么对应？

来源：第 34 章 · 加入 2026-11-15 · 复习记录：

答案

① 实现：普通 C++ 函数（TORCH_CHECK 检查、contiguous() 后取 data_ptr、at::parallel_for 多线程）；② TORCH_LIBRARY(ns, m) { m.def("op(Tensor x, Tensor y) -> Tensor"); } 声明签名 = 分派表加一行；③ TORCH_LIBRARY_IMPL(ns, CPU, m) { m.impl("op", &fn); } 按设备登记 = 填一列（有 CUDA 实现再写一个 IMPL）。fake 和反向可在 Python 里补。

口诀：实现 + TORCH_LIBRARY 加一行 + TORCH_LIBRARY_IMPL 按设备填一列。

P126 · load_inline 和 setup.py 两种构建方式怎么选？本机踩到了什么坑？

来源：第 34 章 · 加入 2026-11-15 · 复习记录：

答案

load_inline / load：Python 里传源码，第一次调用时即时编译（本机约 5–7 秒），适合实验和学习；setup.py + CppExtension / CUDAExtension：pip install . 预编译，适合发布。都需要 ninja 和 C++ 编译器（CUDA 还要 nvcc）。

P127 · 本章 relu(x + y) 四种实现的实测时间是多少？有哪三个教训？

来源：第 34 章 · 加入 2026-11-15 · 复习记录：

答案

2²⁴ 个 float32，本机 6 线程：eager 1.75 ms、C++ -O0 107.4 ms、C++ -O3 1.70 ms、torch.compile 1.18 ms。

口诀：-O3 先写对，手写不自动赢，三方实测再定。

P128 · 对称量化怎么算？[−0.6, 0.2, 1.0] 量化成 int8 和 int4 各是什么？

来源：第 35 章 · 加入 2026-11-15 · 复习记录：

答案

s = max|w| / (2^(b−1) − 1)，q = round(w / s)，还原 ŵ = q × s。

int8：s = 1/127，q = [−76, 25, 127]，还原 [−0.598, 0.197, 1.0]，最大误差 0.003。int4：s = 1/7，q = [−4, 1, 7]，还原 [−0.571, 0.143, 1.0]，最大误差 0.057。int4 格子粗 18 倍，要分组（每 32 / 64 / 128 个共用一个 s）。

口诀：s 等于最大绝对值除以 127，存 round(w/s)，用时乘回 s。

P129 · weight-only 量化和动态激活量化有什么区别？为什么 LLM decode 偏爱 weight-only？

来源：第 35 章 · 加入 2026-11-15 · 复习记录：

答案

weight-only：只把权重存成 int8 / int4，计算时反量化回 bf16 再乘；动态激活：激活也按当前值现算缩放量化，做 int8 × int8 矩阵乘。

decode 访存受限，速度上限 = 带宽 ÷ 权重字节，权重字节变少直接提速（bf16 → int4 理论 ×4，实际 2–3 倍）。实测 torchao Int8WeightOnlyConfig：8.01 → 2.02 MB，输出相对误差 0.56%，权重变成 Int8Tensor 张量子类。

口诀：decode 吃带宽，weight-only 最划算。

P130 · torch.export 和 torch.compile 有什么区别？动态维度怎么声明？

来源：第 35 章 · 加入 2026-11-15 · 复习记录：

答案

compile 边跑边编，允许断图回 Python；export 要一张完整的图，抓不下就报错，输出 ExportedProgram（参数 + ATen 算子图，可序列化）。实测两层 MLP 导出成 linear → gelu → linear。

默认按示例输入固定形状；变的维度：Dim("batch", min=1, max=64)，dynamic_shapes={"input": {0: batch}}。自定义算子要有 fake 实现。

口诀：export 抓整图、抓不下就报错，Dim 声明会变的维。

P131 · AOTInductor 是什么？部署路线怎么选？

来源：第 35 章 · 加入 2026-11-15 · 复习记录：

答案

用 Inductor 提前把 ExportedProgram 编成机器码打成 .pt2 包：aoti_compile_and_package(ep)，Python 里 aoti_load_package(path) 或 C++ 里加载（不需要 Python）。实测打包约 4 秒，batch 5 输入能跑、结果一致。

P132 · 测 kernel 时间有哪四个坑？

来源：第 36 章 · 加入 2026-11-15 · 复习记录：

答案

① 没热身：首次慢很多（实测 2.43 ms vs 之后中位 0.42 ms）；② 没同步（GPU）：只测到下单；③ 只测一次：波动大，要多次取中位数看 IQR；④ 线程数不一致：torch.utils.benchmark.Timer 默认 num_threads=1（实测 0.70 ms vs 6 线程 0.42 ms）。GPU 上用 triton.testing.do_bench，还会清 L2 缓存。

口诀：先热身、要同步、多次取中位、线程数一致。

P133 · 有效带宽怎么算？relu(x + y)（2²² 个 float32）0.70 ms 时是多少？

来源：第 36 章 · 加入 2026-11-15 · 复习记录：

答案

有效带宽 = 必须读写的字节 ÷ 实测时间。relu(x + y) 读 x、y 写结果：3 × 2²² × 4 = 50.3 MB，÷ 0.70 ms ≈ 72 GB/s。和硬件峰值比才知好坏，GPU 上好 kernel 能到 80–90%；分子用"必须"的字节，kernel 多读写了就会暴露。

口诀：有效带宽是必须字节除以时间，和峰值比才知好坏。

P134 · assert_close 的判定公式和默认容差？低精度 kernel 应该和什么比？

来源：第 36 章 · 加入 2026-11-15 · 复习记录：

答案

|a − b| ≤ atol + rtol × |b|。默认：float32 rtol 1.3e−6、atol 1e−5（实测 1.0 上加 1e−5 过、1e−3 不过）；bfloat16 rtol 1.6e−2、atol 1e−5（0.016 过、0.03 不过）；float16 rtol 1e−3。

参考实现用高精度（fp32 / fp64）算；新 kernel 的误差不应明显大于"参考实现也用低精度跑"的误差；反向也要比（gradcheck 或对参考梯度）。

口诀：assert_close 按 dtype 定容差，参考用高精度、反向也要比。

P135 · 新 kernel 的测试矩阵要覆盖哪些维度？一个融合 kernel 的完整生命周期是哪八步？
