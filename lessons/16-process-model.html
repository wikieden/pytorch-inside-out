本章缩写：SPMD = Single Program, Multiple Data（单 / 程序、多 / 数据）；NCCL = NVIDIA Collective Communications Library（NVIDIA 集合 / 通信 / 库，读作 "nickel"）；Gloo = Facebook 的 CPU 通信库（名字不是缩写）；c10d = PyTorch 分布式通信层的名字（c10 + distributed）；rdzv = rendezvous（会合，进程们互相找到对方）；全部缩写见 附录 · 缩写与术语表

讲解

第一步：SPMD——同一份脚本，跑 N 份（2026-11-14）

类比：考场。 8 个考生（进程）拿到同一份试卷（脚本），但每人有自己的座位号（rank），试卷上写着"座位号 0 的做第 1 题，座位号 1 的做第 2 题……"。大家各自做，需要对答案时再通过监考（通信库）交换。

PyTorch 多卡训练的主流做法就是这样，叫 SPMD：

  • 每张 GPU 一个进程，8 卡就是 8 个 Python 进程；
  • 每个进程跑完全相同的脚本；
  • 脚本里用自己的编号决定"用哪张卡、读哪部分数据"。

为什么不用一个进程管 8 张卡（老的 nn.DataParallel 就是这样）？因为 Python 有全局解释器锁（GIL，Global Interpreter Lock），一个进程同一时刻只能跑一个线程的 Python 代码，8 张卡排队等一个 Python，跑不满。

一句话：多卡训练 = 每卡一个进程跑同一份脚本，靠编号分工。

第二步：三个编号（2026-11-14）

编号 意思 2 台机器 × 4 卡的例子
world_size 一共几个进程 8
rank 我是全局第几号（0 到 world_size − 1） 机器 0 上是 0–3，机器 1 上是 4–7
local_rank 我是本机第几号 → 决定用哪张卡 两台机器上都是 0–3

数字演示：机器 1 上的第 2 张卡：local_rank = 2，rank = 1 × 4 + 2 = 6。

代码里：

import os, torch, torch.distributed as dist
dist.init_process_group("nccl")                       # 进程们互相找到对方，建立通信
local_rank = int(os.environ["LOCAL_RANK"])
torch.cuda.set_device(local_rank)                     # 我用第 local_rank 张卡
rank, world = dist.get_rank(), dist.get_world_size()

rank 0 的特殊身份：习惯上只有 rank 0 打日志、存 checkpoint（第 22 章的分布式 checkpoint 例外，要大家一起存）。其他 rank 也打印的话，屏幕上会有 8 份重复输出。

一句话：world_size 是总人数，rank 是全局座位号，local_rank 是本机座位号（决定用哪张卡）；rank 0 管日志。

第三步：torchrun 帮你起进程、发编号（2026-11-14）

你不用自己开 8 个进程。torchrun 负责：在每台机器上起 N 个进程，给每个进程设好环境变量，让它们通过 rendezvous（会合） 互相找到。

# 单机 8 卡
torchrun --nproc_per_node=8 train.py

# 两台机器各 4 卡（两台都要执行，node_rank 不同）
torchrun --nnodes=2 --nproc_per_node=4 --node_rank=0 \
         --rdzv_backend=c10d --rdzv_endpoint=$MASTER_IP:29500 train.py

torchrun 给每个进程设的环境变量：RANK、LOCAL_RANK、WORLD_SIZE、MASTER_ADDR、MASTER_PORT。init_process_group 读这些变量连到"主节点"的那个端口，大家报到齐了才往下走。

本机实测（Mac，2 个进程，Gloo 后端）：

[rank 0] LOCAL_RANK 0 WORLD_SIZE 2 MASTER 127.0.0.1 29511
[rank 1] LOCAL_RANK 1 WORLD_SIZE 2 MASTER 127.0.0.1 29511

Mac 上的坑：直接 torchrun --nproc_per_node=2 会卡住不动（Gloo 找错了网卡）。要指定本地回环：

GLOO_SOCKET_IFNAME=lo0 torchrun --nproc_per_node=2 --master_addr=127.0.0.1 --master_port=29511 script.py

一句话：torchrun 起进程、设 RANK / LOCAL_RANK / WORLD_SIZE / MASTER_ADDR，进程们在主节点会合；Mac 上要指定 lo0。

第四步：通信后端与数据切分（2026-11-14）

后端 用在 说明
NCCL GPU 之间 NVIDIA 的库，走 NVLink（机内卡间高速互连）和 InfiniBand / RoCE（机间网络），GPU 训练只用它
Gloo CPU 之间 本机练习、CPU 训练、部分控制信息
MPI 超算集群 要另外编译

每个进程要读不同的数据，不然 8 张卡算的是同一批，白算。用第 8 章说过的 DistributedSampler：

sampler = DistributedSampler(dataset)          # 自动读 rank、world_size
loader = DataLoader(dataset, batch_size=32, sampler=sampler)
for epoch in range(E):
    sampler.set_epoch(epoch)                   # 每轮打乱方式不同
    for x, y in loader: ...

它把下标按 rank 隔着分：rank 0 拿 0、8、16……，rank 1 拿 1、9、17……。这时 batch_size=32 是每张卡 32，全局 batch = 32 × 8 = 256。

一句话：GPU 用 NCCL、CPU 用 Gloo；DistributedSampler 让每个 rank 读不同样本，全局 batch = 每卡 batch × 卡数。

动画演示：2 台机器 × 4 卡的编号

可交互版：animations/16-ranks.html。滑块调机器数和每台卡数。

怎么看：

  1. 每个方块是一个进程（一张卡），上面写 rank，下面写 local_rank；
  2. 播放时 torchrun 依次在每台机器上起进程，所有进程连到主节点会合；
  3. 最后每个进程领到自己那份数据下标（DistributedSampler 隔着分）。

数学原理

  • rank 编号：\(\text{rank} = \text{node\_rank} \times \text{nproc\_per\_node} + \text{local\_rank}\)。
  • DistributedSampler 的切分：rank \(r\) 拿下标 \(\{r, r + W, r + 2W, \dots\}\)（W = world_size；打乱时先打乱再这样取），样本数不能整除时默认补齐重复几个。
