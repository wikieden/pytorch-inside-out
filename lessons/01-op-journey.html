讲解

第一步：numpy 已经能算，PyTorch 多了两件大事（2026-11-05）

先看一行代码：

y = x @ w        # x 是输入，w 是权重，@ 是矩阵乘法

numpy 也能写这行，算出来的数一模一样。那为什么训练模型都用 PyTorch？因为训练要的不只是"算出 y"，还要两件 numpy 不管的事：

  1. 在 GPU 上算。模型里有上亿次乘加，CPU 太慢。PyTorch 里同一行代码，只要 x、w 放在 GPU 上（x = x.to("cuda")；Mac 上是 "mps"），就自动换成 GPU 版本去算，代码一个字不用改。
  2. 自动求导（autograd）。训练 = 不断调整 w，让结果变好。"往哪个方向调、调多少"要靠梯度（结果对 w 的变化有多敏感）。PyTorch 在你算 y 的同时，悄悄记下"y 是怎么算出来的"；之后调一句 loss.backward()，它就照着这份记录倒推出每个参数的梯度。你只写前向，反向它帮你做。

类比：做菜。 numpy 是一个只会炒菜的厨师。PyTorch 是一整家餐厅： - 有好几个厨房（CPU 厨房、GPU 厨房），大单子送去火力猛的 GPU 厨房； - 每做一道菜，旁边有个记账员把"用了哪些原料、按什么顺序做的"记在账本上。以后想知道"盐多放一点味道会怎么变"，翻账本倒着查就行，不用重做实验。

要不要记账，你说了算：给参数打上 requires_grad=True（nn.Linear 里的权重默认就是），用到它的运算才会被记账。推理时不需要梯度，可以包在 torch.inference_mode() 里，整段都不记，省时间也省显存。

一句话：PyTorch = 能在 GPU 上跑的 numpy + 一个自动记账、能倒推梯度的记账员；在这之上再加 nn（搭模型）、optim（调参数）、DataLoader（喂数据）、distributed（多卡）等工具。

第二步：一行代码经过的四站（2026-11-05）

你按下回车，y = x @ w 在 PyTorch 里走了四站。还是用餐厅来对照：

站 PyTorch 里叫 餐厅里是 做什么
① Python 前端 服务员 接住你写的 x @ w，翻译成 C++ 能懂的一张单子（PyTorch 的核心是 C++ 写的，Python 只是外壳）
② 分派器（Dispatcher） 前台调度 看单子上的标签决定交给谁：要不要记账？去哪个厨房？
③ Autograd（记账） 记账员 如果 x 或 w 要求梯度，就在账本上记一笔"这里做过一次矩阵乘法，用的是 x 和 w"；不要求就跳过这一站
④ Kernel（厨房） 厨房 真正做乘法的那段代码。CPU 厨房和 GPU 厨房各有一份，前台按 x 在哪个设备上选一个

分派器到底看什么：每个张量身上贴着几个标签，比如"要记账"、"在 GPU 上"。分派器按固定顺序处理标签：先处理"要记账"（交给第 ③ 站记一笔），记完把这个标签撕掉，再看"在哪个设备"（交给第 ④ 站对应的厨房）。所以准确地说，分派器是被问了两次：第一次决定"记不记账"，第二次决定"哪个厨房"。

（2026-11-14 补充：为了好懂，这里把"要记账"说成一张有或没有的标签。实际上 CPU / GPU 张量身上一直带着 Autograd 标签，记账员每次都会被叫到，他看一眼"有没有输入要梯度"，没有就什么都不记、直接放行。效果和"跳过这一站"一样。准确版本见第 3 章。）

结果上能看到的痕迹：算完的 y 身上带着一张小纸条 grad_fn=<MmBackward0>，意思是"我是由一次矩阵乘法（mm）算出来的，反向时找 MmBackward0"。这就是第 ③ 站记下的那一笔。没记账时，y.grad_fn 是 None。

import torch
x = torch.randn(2, 3)
w = torch.randn(3, 4, requires_grad=True)   # w 要求梯度 → 会记账
y = x @ w
print(y.grad_fn)        # <MmBackward0 object at ...>

with torch.inference_mode():                # 这一段都不记账
    y2 = x @ w
print(y2.grad_fn)       # None

为什么要拆成这么多站：因为"记账"、"选厨房"互不相干，拆开以后可以随意组合。以后要加新功能，比如"自动把数换成更省空间的低精度"（混合精度，第 26 章），只要在分派器里多加一种标签、多加一站，上千个算子都不用改。

一句话：一行 x @ w = 服务员接单（Python 前端）→ 前台看标签（分派器）→ 需要的话记账员记一笔（autograd）→ 对应设备的厨房做菜（kernel）。

数学原理

  • 梯度：\(\frac{\partial L}{\partial w}\)，结果 \(L\) 对参数 \(w\) 的变化有多敏感；训练按 \(w \leftarrow w - \eta \frac{\partial L}{\partial w}\) 更新（\(\eta\) 是学习率）。第 4 章展开。
  • 为什么记账就能求导：任何复杂计算都是一串简单运算拼起来的；每个简单运算的导数公式已知，链式法则把它们乘起来就是整体的导数。账本记下"拼的顺序"，反向就是按这个顺序倒着乘。第 4 章展开。

公式 / 代码清单

写法 意思
x.to("cuda") / x.to("mps") 把张量搬到 GPU（Mac 上是 MPS），之后的运算自动走 GPU 厨房
requires_grad=True 要求记账，用到它的运算会被记录
y.grad_fn y 是由哪种运算算出来的（账本上的那一笔）；没记账时为 None

loss.backward() 照账本倒推梯度（第 4 章）

关键几行：

x = torch.randn(2, 3, device=device)
w = torch.randn(3, 4, device=device, requires_grad=requires_grad)
y = x @ w                       # 前端 → 分派器 → autograd → kernel
y.grad_fn                       # 记了账就是 <MmBackward0>，没记就是 None

代码里才看得到的 2 件事：

  1. grad_fn 的类名后面带 0：MmBackward0 里的 0 是版本号，不是第 0 个节点。
  2. device 一个参数就换厨房：同一个 journey 把 device 换成 "mps" 就走 GPU，函数体一个字不用改。
