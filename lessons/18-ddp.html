本章缩写：DDP = DistributedDataParallel（分布式 / 数据 / 并行）；MB = megabyte（兆字节）；全部缩写见 附录 · 缩写与术语表

讲解

第一步：数据并行的思路（2026-11-14）

类比：多个厨师照同一份菜谱练手。 每个厨师（卡）有一模一样的菜谱（模型），各自用不同的食材（数据）做一道菜，各自总结"菜谱哪里该改"（梯度）。改之前大家把意见平均一下，于是每人都按同样的意见改，菜谱始终保持一致。

数学上为什么对：一个大 batch 的平均梯度 = 各个小 batch 平均梯度的平均（每卡 batch 一样大时）。所以 N 张卡、每卡 b 个样本，等价于一张卡跑 N × b 个样本。

一句话：数据并行 = 每卡一份完整模型、吃不同数据，梯度平均后一起更新，参数始终一致。

第二步：DDP 做的三件事（2026-11-14）

model = DDP(model.to(local_rank), device_ids=[local_rank])
什么时候 做什么 实测（2 进程）
① 包装时 broadcast rank 0 的参数给所有人，保证起点一致 两个 rank 故意用不同随机种子初始化，包装后权重都变成 [[−0.0053, 0.3793]]
② 反向时 梯度算好一批就 all_reduce 一批，然后除以 N 取平均 rank 0 梯度 [1, 0]，rank 1 梯度 [0, 1] → 两人都是 [0.5, 0.5]
③ 更新时 什么都不用做：大家梯度一样、参数一样，各自 opt.step() 结果自然一样 —

注意第 ② 步是平均不是求和：DDP 在 all_reduce 后除以 world_size，所以学习率不用跟着卡数改（但全局 batch 变大了，通常还是会调学习率）。

优化器状态每卡各存一份完整的。这就是 DDP 的显存问题：参数、梯度、优化器状态 N 张卡各存一份，一点没省（第 19 章 FSDP 解决）。

一句话：DDP = 开始时广播参数 + 反向时 all_reduce 平均梯度；更新各自做；显存一点不省。

第三步：分桶 + 重叠——把通信藏起来（2026-11-14）

最笨的做法：整个反向算完，再一次性 all_reduce 全部梯度。通信时 GPU 在干等。

第一个优化：重叠（Playbook 第 604 行）。反向是从最后一层往前算的，最后一层的梯度最先算好。不用等全部算完，某层梯度一好就发，通信和"前面几层的反向"同时进行。DDP 靠给每个参数注册 hook（第 7 章），梯度一算好 hook 就被触发。

第二个优化：分桶（Playbook 第 645 行）。每个参数单独发一次 all_reduce，几百次小通信，启动开销太大。DDP 把参数按反向的顺序装进一个个桶（bucket，默认 25 MB），一个桶里的梯度全部算好，就把整桶一次发出去。

数字演示：一个模型反向分 4 段，每段算 10 ms；每个桶 all_reduce 要 8 ms（先不算每次通信的启动开销；动画里每次多算 1 ms）。

方式 时间线 总用时
算完再发 反向 40 ms，再通信 4 × 8 = 32 ms 72 ms
分桶重叠 桶 1 在第 10 ms 开始发，和后面的反向并行；只有最后一个桶（最前面几层）的 8 ms 露在外面 约 48 ms

bucket_cap_mb 可以调：桶太小，通信次数多、启动开销大；桶太大，第一个桶要等很久才发，重叠变少。AISPE ch04 第 113–122 行讲了桶大小的取舍。

一句话：反向从后往前，梯度好一桶发一桶，通信藏在前面几层的计算后面；桶大小是"次数"和"重叠"的折中。

第四步：梯度累积要用 no_sync（2026-11-14）

想要大 batch 但显存不够时，攒 k 个小 batch 的梯度再更新一次（第 9 章）。在 DDP 里，每次 backward 都会触发 all_reduce。前 k − 1 次的通信是白费的（反正还没到更新的时候）。

for i, (x, y) in enumerate(loader):
    ctx = model.no_sync() if (i + 1) % k != 0 else contextlib.nullcontext()
    with ctx:                                   # 前 k-1 次：只在本地累加梯度，不通信
        loss = loss_fn(model(x), y) / k
        loss.backward()
    if (i + 1) % k == 0:                        # 第 k 次：backward 时才 all_reduce
        opt.step(); opt.zero_grad()

（Playbook 第 665 行"Interplay with gradient accumulation"。）

另外两个常见报错：

  • 有参数没参与 loss（比如某个分支这一步没走）：DDP 一直等那个参数的梯度，报错。修模型，或设 find_unused_parameters=True（每步多一次遍历，慢）；
  • 每步用的参数集合固定时，设 static_graph=True 可以让 DDP 做更多优化。

一句话：梯度累积的前 k − 1 步包在 no_sync() 里省通信；有参数没进 loss 会报错。

怎么看：

  1. 上面一行是反向计算（从最后一层往前），下面一行是通信；
  2. 算完再发：通信整块排在反向后面；
  3. 分桶重叠：每个桶的梯度一凑齐，通信条就开始，和后面的计算并排；

数学原理

  • 梯度平均等价于大 batch：\(\frac{1}{N}\sum_{r=1}^{N}\frac{1}{b}\sum_{i \in B_r}\nabla \ell_i = \frac{1}{Nb}\sum_{i}\nabla\ell_i\)。
  • 重叠后的通信暴露时间 ≈ 最后一个桶的通信时间（若每桶通信 ≤ 每段计算）。
