讲解

第一步：Tensor = 一排数 + 说明书（2026-11-14）

内存是一维的，像一条很长的走廊，每个格子放一个数。可我们要的是 2 行 3 列的表格。怎么办？

类比：电影院座位。 电影院的座位票其实是从 0 开始连续编号的（0、1、2、3…）。要说"第 1 排第 2 座"，就得知道"每排几个座"：第 1 排第 2 座 = 1 × 3 + 2 = 5 号。

Tensor 就是这样：

部分 叫什么 例子 x = torch.arange(6).view(2, 3)
一排数 storage（存储） [0, 1, 2, 3, 4, 5]
几行几列 shape（形状，也叫 size） (2, 3)
每个维度走一步跳几格 stride（步长） (3, 1)：换一行跳 3 格，换一列跳 1 格
从第几格开始 storage_offset（偏移） 0
每个数什么类型 dtype torch.int64
放在哪 device cpu

取元素的公式：

\[\text{x}[i, j] \text{ 在 storage 的位置} = \text{offset} + i \times \text{stride}_0 + j \times \text{stride}_1\]

读法：offset 加上"行号乘行步长"再加"列号乘列步长"。

数字演示：x[1, 2] → 0 + 1 × 3 + 2 × 1 = 5，storage 第 5 格就是 5 ✓。

x = torch.arange(6).view(2, 3)
x.shape, x.stride(), x.storage_offset()   # (torch.Size([2, 3]), (3, 1), 0)

一句话：Tensor 不是"一张表"，而是"一排数 + 一张怎么把它看成表的说明书（shape、stride、offset）"。

第二步：view 只改说明书，不搬数（2026-11-14）

既然"表格"只是说明书，那很多操作只要改说明书，数一个都不用动。这类操作叫 view（视图），结果和原张量共用同一块 storage。

转置 x.t()：行列互换。不搬数，只把 shape 和 stride 都对调：

shape stride offset
x (2, 3) (3, 1) 0
x.t() (3, 2) (1, 3) 0

验证：x.t()[2, 1] 应该等于 x[1, 2] = 5。用公式：0 + 2 × 1 + 1 × 3 = 5 ✓。

切片 x[:, 1:]（每行去掉第 0 列）：shape (2, 2)，stride 还是 (3, 1)，offset 变成 1。[0, 0] 位置 = 1 + 0 + 0 = 1 ✓（原来的 x[0, 1]）。

证明共用内存：改视图，原张量跟着变。

t = x.t()
t[0, 0] = 100
x[0, 0]                       # tensor(100)：改的是同一格
x.data_ptr() == t.data_ptr()  # True

常见的 view 操作：view、t / transpose / permute、切片、unsqueeze / squeeze、expand、narrow、unflatten。

一句话：view = 新说明书 + 旧 storage；几乎零开销，但改一个另一个也变。

第三步：contiguous——说明书是不是"老老实实按行排"（2026-11-14）

contiguous（连续）：stride 恰好是"行优先、紧挨着排"的那一种。shape (2, 3) 的标准 stride 是 (3, 1)；shape (3, 2) 的标准 stride 是 (2, 1)。

x.t() 的 shape 是 (3, 2)，stride 却是 (1, 3)，不是标准的 (2, 1)，所以 不连续：

x.is_contiguous()      # True
x.t().is_contiguous()  # False

为什么 view 会报错：view(6) 要把张量"拉成一行"，要求按行读出来的顺序正好是 storage 里的顺序。x.t() 按行读是 0, 3, 1, 4, 2, 5，而 storage 里是 0, 1, 2, 3, 4, 5，光改说明书做不到，只能真的搬数。所以：

写法 结果
x.t().view(6) 报错（RuntimeError：view size is not compatible…）
x.t().contiguous().view(6) 先复制成标准排法，再 view：[0, 3, 1, 4, 2, 5]
x.t().reshape(6) 能 view 就 view，不能就自动复制，结果同上

为什么在乎连续：很多 kernel 假设数据连续，碰到不连续的输入会先偷偷复制一份；GPU 读不连续的内存也更慢（读相邻元素要跳着读）。性能分析里看到莫名其妙的 copy_ / contiguous，多半是这里来的。

一句话：contiguous = 按行老实排；转置、permute 后通常不连续，view 不了就用 reshape 或先 .contiguous()（会复制）。

第四步：stride = 0——不复制的"广播"（2026-11-14）

stride 可以是 0：这一维走一步，内存一格不动，等于同一个数被"看"了很多遍。

b = torch.tensor([10, 20, 30])        # shape (3,), stride (1,)
B = b.expand(4, 3)                     # shape (4, 3), stride (0, 1)

4 行都读同一段内存，没有复制。对比 b.repeat(4, 1)：真复制出 12 个数。广播加法 x + b（第 11 章）内部就是这么做的。

一句话：stride 0 = 一份数据假装成很多份；expand 不花内存，repeat 才真复制。

怎么看：

  1. 下面一排是 storage（一维内存），上面是按说明书摆出来的表格；
  2. 依次点亮表格的每个格子，连线指向它在 storage 里的那一格，旁边写出 offset + i × stride₀ + j × stride₁ 的算式；
  3. 注意转置时连线是"跳着"读的，这就是不连续；expand 时几行连到同一段内存。

一排数加说明书：shape 说几行几列，stride 说一步跳几格，offset 说从哪开始；
view 只换说明书，转置跳着读不连续；stride 为 0 一份当多份。

数学原理

  • 行优先（row-major）的标准 stride：shape \((d_0, d_1, \dots, d_{n-1})\) 的 contiguous stride 是 \(s_k = \prod_{m>k} d_m\)，最后一维是 1。例：(2, 3, 4) → (12, 4, 1)。
  • 转置 = 交换 stride：对调第 a、b 维时，shape 和 stride 的第 a、b 项一起对调，storage 不动。

关键几行：

x = torch.arange(6).view(2, 3)
x.stride(), x.storage_offset()           # (3, 1), 0
t = x.t()                                # 只改说明书：stride (1, 3)
x.data_ptr() == t.data_ptr()             # True：共用一块内存
t.view(6)                                # RuntimeError：不连续
t.reshape(6)                             # 能 view 就 view，不能就复制

代码里才看得到的 2 件事：

  1. x[:, 1:] 也不连续：shape (2, 2) 的标准 stride 是 (2, 1)，它是 (3, 1)，is_contiguous() 为 False。
  2. 报错信息很长：view size is not compatible with input tensor's size and stride，看到它就想到第三步。
