讲解

第一步：为什么不能直接调用（2026-11-15）

你写了一个快的 kernel（Triton、C++、甚至调了别的库），包成一个 Python 函数直接用。问题出在 PyTorch 的几个"系统"都不认识它：

系统 不认识会怎样
Autograd（第 4 章） 没有反向公式，训练时梯度断了
torch.compile（第 6 章） Dynamo 要钻进函数里去追踪；遇到它看不懂的东西（ctypes 调用、外部 C 扩展、Triton launch 的某些写法）就断图，或者追踪出错
torch.export（第 35 章） 导不出来
分派器（第 3 章） 不能按设备分派，不能被 vmap 等变换处理

注册就是把它登记进第 3 章那张"算子 × 标签"的大表，成为和 aten::mm 平起平坐的算子。

一句话：直接调用的函数 autograd、compile、export 都不认识；注册后它就成了分派表里的正式算子。

第二步：custom_op + register_fake（2026-11-15）

import torch
from torch import Tensor

@torch.library.custom_op("mylib::add_relu", mutates_args=())   # 名字是 "命名空间::算子名"
def add_relu(x: Tensor, y: Tensor) -> Tensor:                   # 类型标注必须写：它就是 schema
    return torch.relu(x + y)        # 真正的实现：这里可以换成 Triton / C++ / 任何东西

@add_relu.register_fake
def _(x, y):
    return torch.empty_like(x)      # 只说"输出长什么样"：形状、dtype、设备，不算数
  • mutates_args=()：声明这个算子不会原地改任何输入。改了的话必须列出来（编译器要据此安排顺序，第 6 章的 functionalize）；
  • 注册后它也出现在 torch.ops.mylib.add_relu，和 torch.ops.aten.mm 同一个地位。

为什么要 fake 实现：torch.compile 和 torch.export 抓图时不真算，用假张量推一遍形状（第 3 章 Meta 那一步）。你的算子里面是个黑盒，编译器不知道输出多大，所以要你告诉它。

实测：

  • 没有 fake 实现的算子，torch.compile(..., fullgraph=True) 报 TorchRuntimeError: RuntimeError when making fake tensor call；
  • 有了以后，f(a, b) = add_relu(a * 2, b).sin() 用 torch._dynamo.explain 看：graphs 1, breaks 0——自定义算子作为一个整体留在图里，前后的 * 2 和 sin 照常被 Inductor 处理。

一句话：custom_op 用类型标注声明签名、mutates_args 声明原地修改；register_fake 告诉编译器输出的形状，不然 compile / export 用不了。

第三步：register_autograd——给它反向公式（2026-11-15）

def setup_context(ctx, inputs, output):
    ctx.save_for_backward(output)           # 反向要用什么就存什么（第 4 章第五步）

def backward(ctx, grad):
    (out,) = ctx.saved_tensors
    g = grad * (out > 0)                    # relu 的导数：输出 > 0 处为 1
    return g, g                             # 对 x、对 y 各返回一个梯度（加法对两边倍数都是 1）

add_relu.register_autograd(backward, setup_context=setup_context)

实测：x = [−2, 1, 3]，y = [1, −3, 1]：

值
x + y [−1, −2, 4]
输出 relu [0, 0, 4]
x.grad、y.grad（对输出求和后反向） [0, 0, 1]、[0, 0, 1]

grad_fn 显示为 GeneratedBackwardFor_mylib_add_relu_defaultBackward：PyTorch 根据你的注册生成了账本节点。

和第 4 章的 torch.autograd.Function 比：功能类似，但 register_autograd 是挂在注册过的算子上的，所以 compile / export 也能看到并正确处理反向。反向本身往往也值得写一个融合 kernel（反向也是访存受限的）。

一句话：register_autograd = setup_context 存东西 + backward 返回每个输入的梯度；挂在算子上，编译器也能处理反向。

第四步：opcheck——注册有没有写对（2026-11-15）

注册写错了（fake 的形状和真实不一致、反向漏了、原地修改没声明……）常常不会立刻报错，而是在编译或某种变换下才出怪问题。opcheck 一次性检查：

torch.library.opcheck(add_relu, (torch.randn(4, requires_grad=True), torch.randn(4, requires_grad=True)))
# {'test_schema': 'SUCCESS', 'test_autograd_registration': 'SUCCESS',
#  'test_faketensor': 'SUCCESS', 'test_aot_dispatch_dynamic': 'SUCCESS'}
检查项 查什么
test_schema 声明的签名和实际行为一致（比如没声明却改了输入）
test_autograd_registration 需要反向的地方确实注册了反向
test_faketensor fake 实现的输出形状、dtype 和真实实现一致
test_aot_dispatch_dynamic 能被 AOTAutograd（第 6 章）以动态形状正确处理

正确性另外测：opcheck 不检查数值对不对，那要用 torch.testing.assert_close 和参考实现（纯 PyTorch 写的版本）对比，多测几种形状、dtype、非连续输入（第 36 章）。反向用第 4 章的 gradcheck。

一句话：opcheck 查注册（签名、反向、fake、动态形状）；数值正确性另用 assert_close 和 gradcheck。

第五步：Triton kernel 用 triton_op（2026-11-15）

如果实现是 Triton kernel，推荐用 torch.library.triton_op 代替 custom_op：

from torch.library import triton_op, wrap_triton

@triton_op("mylib::add_relu_triton", mutates_args={})
def add_relu_triton(x: Tensor, y: Tensor) -> Tensor:
    out = torch.empty_like(x)
    n = x.numel()
    wrap_triton(add_relu_kernel)[(triton.cdiv(n, 1024),)](x, y, out, n, BLOCK=1024)   # 第 32 章的 kernel
    return out

区别：custom_op 对编译器是黑盒；triton_op 让 Inductor 能看到里面的 Triton kernel，可以和前后的生成代码一起调度（AISPE ch14 第 1257–1323 行的注册示例）。fake 实现它多数情况能自己推出来，反向照样用 register_autograd。[GPU]：Mac 上没有 Triton，本章这一步只能在 Linux + GPU 上跑。

一句话：Triton kernel 用 triton_op + wrap_triton 注册，编译器能看进去一起优化。

数学原理

  • 加法的反向：\(z = x + y\)，\(\frac{\partial z}{\partial x} = \frac{\partial z}{\partial y} = 1\)，所以两个输入拿到同一个上游梯度。
  • ReLU 的反向：\(\frac{d}{du}\max(u, 0) = [u > 0]\)；用输出判断（输出 > 0 ⇔ 输入 > 0）可以只存输出，省一份显存。
