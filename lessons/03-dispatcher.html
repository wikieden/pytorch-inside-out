讲解

第一步：看一眼真实的标签（2026-11-14）

PyTorch 提供了一个内部函数，能直接看张量身上的标签（dispatch key，分派键）：

x = torch.randn(2, 3)
torch._C._dispatch_keys(x)
# DispatchKeySet(CPU, ADInplaceOrView, AutogradCPU, AutocastCPU)

在 Mac 的 GPU（MPS）上：

torch._C._dispatch_keys(torch.randn(2, device="mps"))
# DispatchKeySet(MPS, ADInplaceOrView, AutogradMPS, AutocastMPS)

四个标签各管一件事：

标签 谁 管什么
AutocastCPU / AutocastMPS 混合精度员 开了 torch.autocast 时，把输入换成低精度（第 26 章）；没开就放行
AutogradCPU / AutogradMPS 记账员 有输入要梯度就记一笔（第 4 章）；没有就放行
ADInplaceOrView 版本登记员 原地修改和 view 时更新"版本号"，防止反向时用到被改过的数（第 4 章第四步）
CPU / MPS / CUDA 厨房 真正计算

补正第 1 章：第 1 章为了好懂，说"不要梯度就没有'要记账'标签"。真实情况是：普通张量身上一直有 Autograd 标签，记账员每次都被叫到，他看一眼"有没有输入 requires_grad=True"，没有就直接放行，什么都不记。

一句话：每个张量带一组标签，一个标签对应一个"工种"；分派器按顺序把活交给各工种。

第二步：顺序——从上往下，每层干完撕掉自己再往下传（2026-11-14）

标签有固定的优先级。简化后的梯子（从上往下处理）：

Autocast        混合精度员：要不要换成 bf16？
   ↓
Autograd        记账员：要不要记一笔？
   ↓
ADInplaceOrView 版本登记员
   ↓
（Python）      张量子类的 __torch_dispatch__，DTensor 就在这一层（第 20 章）
   ↓
CPU / CUDA / MPS / Meta   厨房

每一层做完自己的事，把自己的标签从"待处理"里去掉，再叫一次分派器（叫 redispatch，再分派），于是活自然落到下一层。

数字演示：在 autocast 里做 x @ w（w 要梯度）：

x = torch.randn(2, 3); w = torch.randn(3, 4, requires_grad=True)
with torch.autocast("cpu", dtype=torch.bfloat16):
    y = x @ w
y.dtype                       # torch.bfloat16
y.grad_fn                     # <MmBackward0>
y.grad_fn.next_functions      # ((None, 0), (<ToCopyBackward0>, 0))

一步步看：

  1. Autocast 层：matmul 在"适合低精度"的名单里，于是把 x、w 转成 bf16。"转换"本身也是运算，也会经过记账员——所以账本上出现了 ToCopyBackward0（把 w 拷成 bf16 的那一步）；
  2. Autograd 层：记下 MmBackward0，它的上游指向那个 ToCopyBackward0；
  3. CPU 厨房：用 bf16 做乘法。

next_functions 里第一项是 None，因为 x 不要梯度，账本上不用为它往回走。

为什么要这样设计：混合精度、记账、换设备是三件互不相关的事。每件事只在自己那层写一次，就对所有算子生效。不然 2000 多个算子 × 每种组合，都得各写一遍。

一句话：标签有顺序：先混合精度，再记账，最后进厨房；每层做完撕掉自己的标签再往下传。

第三步：每个算子一张"标签 → 实现"的表（2026-11-14）

分派器手里有一张大表：行是算子，列是标签，格子里是那一层用的函数。

算子 Autocast 列 Autograd 列 CPU 列 CUDA 列 Meta 列
aten::mm 转 bf16 记 MmBackward0 CPU 矩阵乘 cuBLAS 只算输出形状
aten::add 不处理 记 AddBackward0 CPU 加法 CUDA kernel 只算形状
  • 这张表的"行"在 PyTorch 源码 aten/src/ATen/native/native_functions.yaml 里声明（每个算子一项，写明有哪些后端实现）；Autograd 那列的反向公式写在 tools/autograd/derivatives.yaml（〔在线〕源码，本地未归档）。
  • 加一个新后端（比如一种新芯片），只需要给它的标签那一列填函数，其他层自动复用。MPS、Intel 的 XPU 就是这么接进来的。
  • 第 33 章自己注册算子，就是往这张表里加一行。

一句话：分派器 = 一张"算子 × 标签"的大表；加功能加一列，加算子加一行。

第四步：两个特别的标签——Meta 和 inference_mode（2026-11-14）

Meta 设备：厨房只算"做出来的菜多大"，不真做。

m = torch.empty(10**6, 10**6, device="meta")    # 名义上 10¹² 个 float32 = 4 TB
(m @ m.T).shape                                 # torch.Size([1000000, 1000000])，瞬间返回
torch._C._dispatch_keys(m)                      # DispatchKeySet(Meta, ADInplaceOrView, AutogradMeta)

用处：

  • torch.compile、torch.export 抓图时要先知道每一步的输出形状，又不想真算（第 6 章，那里叫 fake tensor，假张量，原理相同）；
  • 超大模型先在 meta 上建好结构，再按分片真正分配内存（第 19 章 FSDP2）：with torch.device("meta"): model = BigModel()。

inference_mode：在 torch.inference_mode() 里新建的张量根本没有 Autograd 标签：

with torch.inference_mode():
    z = torch.randn(2)
torch._C._dispatch_keys(z)     # DispatchKeySet(CPU, AutocastCPU)

连"看一眼"都省了，所以比 no_grad 还快一点；代价是这种张量以后不能参与要求导的计算。

一句话：Meta = 只算形状不算数；inference_mode = 把记账员和版本登记员整个拿掉。

口诀

张量身上贴标签，分派器按梯子往下传：
先混合精度，再记账，再版本登记，最后进厨房；
每层干完撕标签；加功能加一列，加算子加一行；Meta 只算形状不算数。

数学原理

本章没有新数学。可以把分派理解成函数组合：一次调用 = \(\text{Autocast} \circ \text{Autograd} \circ \text{ADInplaceOrView} \circ \text{Kernel}\)，每一层要么做事再往下调，要么直接"穿透"（fallthrough）。
