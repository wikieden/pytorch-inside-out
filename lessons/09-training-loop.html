讲解

第一步：五行主干（2026-11-14）

所有训练循环的骨架都是这五行：

for x, y in loader:
    pred = model(x)                 # ① 前向：算预测，同时记账（第 4 章）
    loss = loss_fn(pred, y)         # ② 算 loss：一个数，越小越好
    opt.zero_grad()                 # ③ 清掉上一步的梯度（第 4 章坑 1）
    loss.backward()                 # ④ 反向：照账本算出每个参数的 .grad
    opt.step()                      # ⑤ 更新：按 .grad 拧参数

类比：投篮练习。 ① 投一次 → ② 看偏了多少 → ③ 把上次的笔记擦掉 → ④ 分析这次手腕、手肘各该怎么调 → ⑤ 照着调。

顺序的讲究：

  • ③ 可以放在 ① 前面，也可以放在 ④ 前面，只要在 backward 之前就行；放到 ⑤ 后面也对（下一步之前清）。不能放在 ④ 和 ⑤ 之间（刚算的梯度就被清了）。
  • ④ 一定在 ⑤ 前面：先有梯度，才能更新。

数字演示：拟合 \(y = 3x + 1\)（32 个点，\(x\) 在 −1 到 1 之间），模型 nn.Linear(1, 1)，SGD，学习率 0.5，MSE loss（预测和答案差的平方的平均）：

步 loss 权重 w 偏置 b
0 3.42 1.06 1.00
1 1.34 1.75 1.00
2 0.56 2.19 1.00
5 0.040 2.78 1.00
10 0.0005 2.98 1.00
20 0.0000 3.00 1.00

（表里是每步更新之后的 w、b，loss 是更新之前算的。b 第一步就到了 1：因为 x 关于 0 对称，b 的梯度正好是 2 ×（b − 1），乘上学习率 0.5 一步到位。）

一句话：前向 → loss → 清梯度 → 反向 → 更新；清梯度只要在 backward 之前。

第二步：护具一——混合精度 autocast（2026-11-14）

float32（单精度）每个数 4 字节；bf16 每个数 2 字节，GPU 的 Tensor Core（张量核心，专门做低精度矩阵乘法的硬件）算它快好几倍。混合精度 = 矩阵乘法这类"不怕精度低"的运算用 bf16，求和、softmax、loss 这类"怕精度低"的用 float32。

with torch.autocast(device_type="cuda", dtype=torch.bfloat16):
    pred = model(x)
    loss = loss_fn(pred, y)
loss.backward()            # backward 放在 autocast 外面
opt.step()

谁用什么精度由第 3 章的 Autocast 层按名单决定，你不用管。参数本身还是 float32，优化器更新也是 float32，所以叫"混合"。

fp16 还要多一样东西 GradScaler（防止小梯度在 fp16 里变成 0），bf16 不用。现在 A100 以后的卡都首选 bf16。第 26 章细讲。

一句话：autocast 包住前向和 loss，矩阵乘法走 bf16、敏感运算留 float32；参数和更新仍是 float32。

第三步：护具二——梯度裁剪（2026-11-14）

偶尔某一步的梯度特别大（比如碰到一个怪样本），一步就把参数拧飞，loss 变成 NaN（Not a Number，非数）。梯度裁剪：把所有参数的梯度拼成一个大向量，算它的长度（范数），超过上限就等比例缩小到上限。

loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)   # 放在 backward 和 step 之间
opt.step()

数字演示：梯度是 [3, 4]，长度 \(\sqrt{3^2 + 4^2} = 5\)，上限 1 → 缩小 5 倍：

p.grad = torch.tensor([3., 4.])
clip_grad_norm_([p], 1.0)       # 返回 5.0（裁剪前的长度）
p.grad                          # tensor([0.6000, 0.8000])

方向不变，只缩长度。返回值是裁剪前的范数，值得每隔几步记进日志：它突然变大往往是训练要出问题的前兆。

一句话：梯度太长就等比例缩到上限，方向不变；放在 backward 和 step 之间，裁剪前的范数记日志。

第四步：护具三——学习率调度（2026-11-14）

学习率太大会冲过头，太小走得慢。实践里学习率随步数变化，大模型最常用的是 warmup + cosine（预热 + 余弦衰减）：

  • 前 W 步从 0 线性升到最大值（刚开始参数是随机的、梯度方向乱，小步走稳一点）；
  • 之后按余弦曲线慢慢降到 0（后期精调）。

数字演示：最大 lr = 3e-4，W = 100，总步数 1000：

步 0 50 100 550 1000
lr 0 1.5e-4 3.0e-4 1.5e-4 0

550 是衰减段的正中间，余弦正好降到一半。用 LambdaLR 最灵活：

def lr_at(s):
    if s < W: return s / W                                    # 返回"最大值的几倍"
    return 0.5 * (1 + math.cos(math.pi * (s - W) / (T - W)))
sched = torch.optim.lr_scheduler.LambdaLR(opt, lr_at)
# 每步：opt.step(); sched.step()     ← sched 在 opt 之后

一句话：学习率先线性升（warmup）再余弦降；sched.step() 放在 opt.step() 之后。

第五步：拼成完整的一步（2026-11-14）

model.train()
for step, (x, y) in enumerate(loader):
    x, y = x.to(dev, non_blocking=True), y.to(dev, non_blocking=True)   # 第 8 章
    with torch.autocast(device_type=dev, dtype=torch.bfloat16):          # 护具一
        loss = loss_fn(model(x), y)
    opt.zero_grad(set_to_none=True)
    loss.backward()
    gnorm = torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)     # 护具二
    opt.step(); sched.step()                                             # 护具三
    if step % 100 == 0:
        print(step, loss.item(), gnorm.item(), sched.get_last_lr()[0])  # 同步点，少打

set_to_none=True（现在是默认值）：把 .grad 设成 None 而不是填 0，省一次写显存。

梯度累积（显存只够小 batch、又想要大 batch 的效果）：每 k 个小 batch 才 step 一次，loss 先除以 k，其间不清零（利用第 4 章的"累加"）。

一句话：完整一步 = 搬数据 → autocast 前向 → 清梯度 → 反向 → 裁剪 → 更新 → 调度 → 偶尔记日志。

口诀

前向、loss、清梯度、反向、更新；清梯度只要在反向前；
autocast 包前向，矩阵走 bf16；裁剪放在反向和更新之间，方向不变只缩长；
学习率先升后余弦降，调度跟在更新后。

数学原理

  • SGD：\(\theta \leftarrow \theta - \eta \nabla_\theta L\)。
  • MSE：\(L = \frac{1}{N}\sum_i (\hat y_i - y_i)^2\)；对偏置的梯度 \(\frac{2}{N}\sum_i(\hat y_i - y_i)\)。\(x\) 对称时 \(\sum x_i = 0\)，所以 \(\partial L/\partial b = 2(b - 1)\)，学习率 0.5 时一步到 1。
  • 梯度裁剪：\(g \leftarrow g \cdot \min\!\left(1, \frac{c}{\lVert g \rVert_2}\right)\)。
  • warmup + cosine：\(\eta_t = \eta_{\max} \frac{t}{W}\)（\(t < W\)）；\(\eta_t = \frac{\eta_{\max}}{2}\left(1 + \cos\frac{\pi (t - W)}{T - W}\right)\)（\(t \ge W\)）。
