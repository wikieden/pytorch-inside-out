讲解

第一步：先量出"等数据"的时间（2026-11-14）

类比：厨房出菜慢，先分清是"等食材"还是"炒得慢"。

最简单的量法：给一步训练拆两段计时。

t0 = time.perf_counter()
for x, y in loader:
    t1 = time.perf_counter()                 # 拿到这一批：t1 - t0 是等数据的时间
    x, y = x.to(dev, non_blocking=True), y.to(dev, non_blocking=True)
    loss = train_step(x, y)
    torch.cuda.synchronize()                 # 只在测量时加！平时不要
    t2 = time.perf_counter()                 # t2 - t1 是训练的时间
    log(data=t1 - t0, compute=t2 - t1)
    t0 = time.perf_counter()

数字演示：测得等数据 18 ms、训练 30 ms → 每步 48 ms，GPU 有 37.5% 的时间在等数据。如果数据时间接近 0，瓶颈就不在数据，别在这里花功夫（第 23 章：只改瓶颈）。

注意那个 synchronize()：为了测准才加（第 5 章），测完要删掉，它本身就是同步点。

一句话：把每步拆成"等数据"和"算"两段计时，数据段接近 0 就别优化数据。

第二步：数据从硬盘到显存的四段路（2026-11-14）

硬盘 ──① 读取──▶ CPU 内存 ──② 解码 / 增强 / 分词──▶ 张量 ──③ 拼 batch──▶ 锁页内存 ──④ 拷进显存──▶ GPU
段 慢的表现 提速办法
① 读取 网络盘、海量小文件 打包成大分片文件（WebDataset、Arrow、二进制 token 文件）；本地 SSD 缓存；np.memmap 按需读
② 处理 图片解码、分词占满 CPU 离线预处理（预先分词存成 token 数组，CS336 a1 就是这么做）；num_workers 并行（第 8 章）；GPU 上做增强
③ 拼 batch 大量 Python 对象 让 __getitem__ 直接返回张量；collate 别做重活
④ 拷贝 拷贝和计算串行 pin_memory=True + non_blocking=True；或者用单独的 stream 提前拷下一批（第 5 章第三步，AISPE ch13 第 1021–1097 行）

LLM 预训练的标准做法：提前把全部语料分词成 uint16 / uint32 的 token 数组存盘，训练时 memmap 打开，每步随机切几个定长片段——第 ① ② ③ 段几乎都没了，只剩一次小拷贝。

一句话：读取、处理、拼 batch、拷贝四段；能离线做的离线做（预分词），剩下的并行（workers）和异步（pin + non_blocking）。

第三步：把同步点一次性揪出来（2026-11-14）

第 5 章列过同步点清单。实际代码里它们常常藏得很深：

藏在哪 例子
日志 wandb.log({"loss": loss.item()}) 每步一次
指标 acc = (pred == y).float().mean().item()
梯度裁剪后看范数 if gnorm > 10: print(...)
数据相关形状 x[mask]、torch.nonzero、torch.unique
默认参数 某些库函数内部调了 .cpu()
CPU 张量参与 GPU 运算 gpu_t * torch.tensor(2.0) 没问题（标量），但 gpu_t[cpu_index_tensor] 会触发拷贝

自动报警（CUDA）：

torch.cuda.set_sync_debug_mode("warn")    # 之后每遇到一次同步就打一条警告
# 或 "error"：直接报错，逼你改掉

改法：

  • 指标在 GPU 上累加：running_loss += loss.detach()，每 100 步才 .item() 一次；
  • if 改 torch.where（第 12 章）；
  • 数据相关形状改成固定形状 + mask。

一句话：同步点常藏在日志、指标、数据相关形状里；set_sync_debug_mode("warn") 帮你全找出来；指标在 GPU 上累计、隔 N 步再取。

第四步：预取到 GPU——让下一批提前到位（2026-11-14）

即便 DataLoader 够快，第 ④ 段拷贝仍可能和计算串在一起。办法：在算这一批的同时，把下一批拷进显存。

class CUDAPrefetcher:
    def __init__(self, loader):
        self.it, self.stream = iter(loader), torch.cuda.Stream()
        self.preload()
    def preload(self):
        try: x, y = next(self.it)
        except StopIteration: self.next = None; return
        with torch.cuda.stream(self.stream):                       # 另一条轨道上拷
            self.next = (x.cuda(non_blocking=True), y.cuda(non_blocking=True))
    def __iter__(self): return self
    def __next__(self):
        if self.next is None: raise StopIteration
        torch.cuda.current_stream().wait_stream(self.stream)       # 用之前等拷贝完成
        batch = self.next
        for t in batch: t.record_stream(torch.cuda.current_stream())  # 告诉分配器：这块显存在主轨道上还在用
        self.preload()                                             # 马上开始拷下一批
        return batch

record_stream 那一行是为了第 5 章的缓存分配器：张量是在拷贝轨道上分配的，如果不告诉分配器它还在主轨道上用，分配器可能提前把这块显存借给别人。

一句话：用第二条 stream 提前拷下一批，用之前 wait_stream，再 record_stream 防止显存被提前回收。

数学原理

  • GPU 忙碌占比 = 计算时间 ÷（计算 + 不能重叠的等待）。数据与计算完全重叠时，每步时间 = max(数据, 计算)；串行时 = 数据 + 计算。
