讲解

第一步：从"一个线程一个数"到"一个 program 一块数"（2026-11-15）

CUDA（SIMT）：你写的是一个线程的代码，自己算"我是第几个线程、管哪个数"，还要操心 warp、共享内存、同步（CUDA 讲义第 1–8 章）。

Triton（块级 SPMD）：你写的是一个 program 的代码，一个 program 一次处理一整块数据（比如 1024 个数），写法像 numpy：对整个块做加法、求最大值。块内怎么分给线程、要不要用共享内存、怎么合并访存，编译器帮你决定（AISPE ch14 第 1144–1170 行）。

类比：搬家公司。 CUDA 是给每个搬运工单独写说明（你搬 3 号箱）；Triton 是给每个小组写说明（你们组负责 3 号房间的所有箱子），组内怎么分工组长自己安排。

一个 program 大致对应 CUDA 里的一个线程块（block）。

一句话：Triton 写的是"一个 program 处理一块数据"，块内的线程分工交给编译器。

第二步：最小的 kernel——五个零件（2026-11-15）

@triton.jit
def add_relu_kernel(x_ptr, y_ptr, out_ptr, n, BLOCK: tl.constexpr):
    pid = tl.program_id(0)                       # ① 我是第几个 program
    offs = pid * BLOCK + tl.arange(0, BLOCK)     # ② 我负责的下标：一整个向量
    mask = offs < n                              # ③ 最后一块可能越界，用 mask 挡住
    x = tl.load(x_ptr + offs, mask=mask)         # ④ 一次读一整块
    y = tl.load(y_ptr + offs, mask=mask)
    tl.store(out_ptr + offs, tl.maximum(x + y, 0), mask=mask)   # ⑤ 算完一次写一整块
零件 意思
tl.program_id(0) 第 0 维上我是第几个 program（像第 16 章的 rank）
tl.arange(0, BLOCK) [0, 1, …, BLOCK − 1] 一个向量；BLOCK 必须是编译期常量（tl.constexpr），通常是 2 的幂
offs 指针加上一个下标向量 = 一整块地址
mask 真假向量；为假的位置 load 不读（可给 other= 默认值）、store 不写
tl.load / tl.store 从显存读一块 / 写一块

启动：

n = x.numel()
grid = lambda meta: (triton.cdiv(n, meta["BLOCK"]),)    # 要几个 program：向上取整
add_relu_kernel[grid](x, y, out, n, BLOCK=1024)

数字演示：n = 2500、BLOCK = 1024 → cdiv(2500, 1024) = 3 个 program：

pid offs 范围 mask 为真的个数
0 0–1023 1024
1 1024–2047 1024
2 2048–3071 452（2048–2499），后 572 个被挡住

这就是第 29 章说的"读一次、写一次"：x、y 各读一遍，结果写一遍，中间的 x + y 只存在于寄存器。

一句话：program_id 定位、arange 拿一块下标、mask 挡越界、load / store 整块读写；grid = 向上取整（n / BLOCK）。

第三步：一行一个 program——行规约（softmax 的结构）（2026-11-15）

softmax、LayerNorm、RMSNorm 都是"每一行独立做一次规约"。Triton 的典型组织：一个 program 处理一整行，grid = 行数。

伪代码（结构，不是完整实现）：

program pid 处理第 pid 行：
    cols = arange(0, BLOCK)              # BLOCK ≥ 行长 N，取 2 的幂
    row  = load(第 pid 行的起点 + cols, mask = cols < N, 越界处补 −∞)
    m    = max(row)                      # 规约 1：tl.max(row, axis=0)
    e    = exp(row − m)                  # 第 13 章：先减最大值
    s    = sum(e)                        # 规约 2：tl.sum(e, axis=0)
    store(输出第 pid 行 + cols, e / s, mask)

为什么越界处补 −∞：exp(−∞) = 0，不影响求和（第 12 章 mask 的同一个道理）；如果补 0，exp(0) = 1 会把分母弄错。

一行读一次、写一次，规约都在片上完成。这就是 Triton 官方教程 02「fused softmax」的结构，Inductor 生成的 triton_per_*（persistent reduction：整行放进一个 program）kernel 也长这样。行太长（几万）放不进一个块时，要循环分段读，配合在线 softmax（第 21 章 CP、CUDA 讲义第 21 章）。

一句话：行规约用"一个 program 一行"，块内 tl.max / tl.sum；越界补 −∞（softmax）或 0（求和），看对结果无影响的值是什么。

第四步：块大小怎么选——autotune（2026-11-15）

BLOCK、num_warps（一个 program 用几个 warp，即几组 32 线程）、num_stages（流水线级数）都会影响速度，和形状、硬件有关，手调很累。

@triton.autotune(
    configs=[triton.Config({"BLOCK": b}, num_warps=w) for b in (256, 512, 1024, 2048) for w in (2, 4, 8)],
    key=["n"],                       # n 变了就重新挑
)
@triton.jit
def add_relu_kernel(x_ptr, y_ptr, out_ptr, n, BLOCK: tl.constexpr): ...

第一次调用时把所有配置都跑一遍，记下最快的；之后同样的 key 直接用。（AISPE ch14 第 1324–1387 行。）

再往深走：矩阵乘用 tl.dot（走 Tensor Core）、二维分块、tl.make_tensor_descriptor（Hopper 的 TMA 搬运）、warp specialization 等（AISPE ch14 第 1388 行起；CUDA 讲义第 13–18 章讲它们底下发生了什么）。

一句话：块大小、warp 数、流水线级数交给 @triton.autotune 实测挑；矩阵乘用 tl.dot。

数学原理

  • grid 大小：\(\lceil n / B \rceil\)；最后一个 program 的有效元素数 \(n - (\lceil n/B \rceil - 1) B\)。
  • mask 的"中性值"：规约运算 ∘ 的单位元 e 满足 \(a \circ e = a\)：求和补 0、求积补 1、求最大值补 −∞（softmax 里 exp(−∞) = 0 同时对求和中性）。

关键几行：

for pid in range(cdiv(n, block)):
    offs = pid * block + torch.arange(block)
    mask = offs < n
    o = offs[mask]
    out[o] = torch.clamp(x[o] + y[o], min=0)

代码里才看得到的 2 件事：

  1. 模拟版是一个 program 接一个跑：真 Triton 是所有 program 同时跑，结果一样、速度不同。
  2. 越界补 −∞ 才对：把 row_softmax_blocked 的 −∞ 改成 0，结果就错了。
