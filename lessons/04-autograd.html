讲解

第一步：梯度是什么——"拧一下旋钮，结果变多少"（2026-11-14）

类比：调音台。 音响有很多旋钮（参数），你想让声音（loss，损失，越小越好）最好。梯度 = 每个旋钮"往右拧一点点，声音变化多少"。知道了每个旋钮的梯度，就知道往哪拧、拧多少。

记号：\(\frac{\partial L}{\partial w}\) 读作"L 对 w 的偏导"，意思是"只动 w、别的不动时，L 变化的速度"。

数字演示：\(L = w^2\)，\(w = 3\)。把 \(w\) 拧到 3.001，\(L\) 从 9 变成 9.006001，变了约 0.006，是 \(w\) 变化量 0.001 的 6 倍。所以 \(\frac{\partial L}{\partial w} \approx 6\)。公式 \(\frac{d}{dw} w^2 = 2w = 6\) ✓。

训练的一步：\(w \leftarrow w - \eta \cdot \frac{\partial L}{\partial w}\)（\(\eta\) 读"伊塔"，学习率，比如 0.1）。梯度是 6，就把 \(w\) 往小拧 0.6。

一句话：梯度 = 结果对每个参数的敏感度；训练就是沿梯度的反方向一点点拧。

第二步：链式法则——一串小步的敏感度相乘（2026-11-14）

模型是一长串简单运算。拿一个小例子：

\[z = w \cdot x + b, \qquad L = z^2\]

取 \(x = 2\)、\(w = 3\)、\(b = 1\)：\(z = 7\)，\(L = 49\)。

想求 \(\frac{\partial L}{\partial w}\)：\(w\) 先影响 \(z\)，\(z\) 再影响 \(L\)。链式法则：两段敏感度相乘。

\[\frac{\partial L}{\partial w} = \frac{\partial L}{\partial z} \cdot \frac{\partial z}{\partial w} = 2z \cdot x = 2 \times 7 \times 2 = 28\]
\[\frac{\partial L}{\partial b} = \frac{\partial L}{\partial z} \cdot \frac{\partial z}{\partial b} = 2z \cdot 1 = 14\]

类比：传话的放大倍数。 \(z\) 每变 1，\(L\) 变 14（\(2z\)）；\(w\) 每变 1，\(z\) 变 2（\(x\)）。所以 \(w\) 每变 1，\(L\) 变 14 × 2 = 28。

PyTorch 里：

x = torch.tensor(2.); w = torch.tensor(3., requires_grad=True); b = torch.tensor(1., requires_grad=True)
L = (w * x + b) ** 2
L.backward()
w.grad, b.grad          # (tensor(28.), tensor(14.))

一句话：链式法则 = 沿着计算路线，把每一小步的放大倍数乘起来。

第三步：账本长什么样——一张倒着走的图（2026-11-14）

前向时每做一次运算，记账员就记一个节点（Node），节点之间用箭头连起来，叫计算图（DAG：有方向、不会绕圈的图）。上面例子的账本：

L ── PowBackward0 ── AddBackward0 ─┬─ MulBackward0 ── AccumulateGrad(w)
                                   └─ AccumulateGrad(b)

在 PyTorch 里能一层层看到：

L.grad_fn                                   # <PowBackward0>
L.grad_fn.next_functions                    # ((<AddBackward0>, 0),)
L.grad_fn.next_functions[0][0].next_functions
# ((<MulBackward0>, 0), (<AccumulateGrad>, 0))   ← 第二个就是 b

backward() 做的事：从 L 出发，按箭头倒着走，每到一个节点，用它的反向公式把"上游传来的梯度"乘上"这一步的放大倍数"，再往下传：

节点 收到 这一步的放大倍数 往下传
PowBackward0（\(z^2\)） 1（\(\partial L / \partial L\)） \(2z = 14\) 14 → Add
AddBackward0（\(+b\)） 14 对两个输入都是 1 14 → Mul，14 → b
MulBackward0（\(w \cdot x\)） 14 对 \(w\) 是 \(x = 2\) 28 → w
AccumulateGrad 28 / 14 — 存进 w.grad / b.grad

几个名词：

  • 叶子（leaf）：自己创建的、不是算出来的张量，比如 w、b。只有叶子的 .grad 会被填上；z 这种中间结果不是叶子，z.grad 是 None。
  • define-by-run（边跑边建）：账本每次前向重新记。所以 Python 的 if、for 想怎么写都行，这一次走了哪条路就记哪条路。
  • 反向公式在 PyTorch 源码 tools/autograd/derivatives.yaml 里，每个算子一条。

一句话：前向记节点连成图，反向从 loss 倒着走，每个节点乘上自己的放大倍数，最后存进叶子的 .grad。

第四步：两个常见坑——梯度会累加、原地修改会报错（2026-11-14）

坑 1：梯度是"加"进 .grad 的，不是"覆盖"。

L.backward(retain_graph=True)   # 第一次：w.grad = 28
L.backward()                    # 第二次：w.grad = 56（28 + 28）

（retain_graph=True 让账本用完先别扔，才能再反向一次；默认反向完账本就释放了，省内存。）

这就是训练循环每步都要 optimizer.zero_grad() 的原因：不清零，这一步的梯度会叠在上一步上。反过来，"故意不清零、攒几步再更新"就是梯度累积（第 18 章、第 25 章用它模拟大 batch）。

坑 2：反向要用的数，前向之后不能原地改。

有些反向公式要用前向时的值，比如 \(\frac{d}{dw} e^w = e^w\)，exp 的反向要用它自己的输出。如果你原地改了这个输出：

a = w.exp()
a.add_(1)              # 原地加 1（带下划线的方法都是原地修改）
a.sum().backward()
# RuntimeError: one of the variables needed for gradient computation has been
# modified by an inplace operation: ... which is output 0 of Exp, is at version 1 ...

PyTorch 怎么发现的：每个张量有个版本号，每次原地修改 +1（第 3 章的 ADInplaceOrView 登记员就在干这个）。记账时存下当时的版本号，反向时一对比，变了就报错。修法：别原地改，写成 a = a + 1。

一句话：.grad 只会累加，每步要清零；反向要用的数被原地改过，版本号对不上就报错。

第五步：自己写反向——torch.autograd.Function（2026-11-14）

大多数时候不用写反向。只有三种情况要自己写：PyTorch 没有的运算（比如自己写的 Triton kernel，第 33 章）、想用更省内存或更稳定的反向公式、想故意"改"梯度（比如直通估计器）。

写法：继承 torch.autograd.Function，写两个静态方法。以 ReLU（Rectified Linear Unit：整流 / 线性 / 单元，\(\max(x, 0)\)）为例：

class MyReLU(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x):
        ctx.save_for_backward(x)          # 反向要用 x，存进 ctx（上下文）
        return x.clamp(min=0)
    @staticmethod
    def backward(ctx, grad_out):          # grad_out = 上游传来的 ∂L/∂输出
        (x,) = ctx.saved_tensors
        return grad_out * (x > 0)         # 放大倍数：x>0 时 1，否则 0

t = torch.tensor([-1., 2., 3.], requires_grad=True)
MyReLU.apply(t).sum().backward()
t.grad                                    # tensor([0., 1., 1.])

怎么确认反向写对了：torch.autograd.gradcheck 用"拧一点点看变化"（第一步的数值方法）和你的公式对比，要用 float64：

torch.autograd.gradcheck(MyReLU.apply, (torch.tensor([-1., 2., 3.], dtype=torch.double, requires_grad=True),))
# True

一句话：自定义反向 = forward 里存好要用的东西，backward 里返回"上游梯度 × 本步放大倍数"；用 gradcheck 对拍。

怎么看：

  1. 前向：从左到右算出 \(z = 7\)、\(L = 49\)，每算一步账本上多一个节点；
  2. 反向：从右往左，箭头上写"收到的梯度 × 放大倍数"，最后落进 w.grad = 28、b.grad = 14；
  3. 点"再反向一次"，.grad 变成 56 / 28：累加而不是覆盖。

数学原理

  • 导数的数值定义：\(f'(w) = \lim_{h \to 0} \frac{f(w+h) - f(w)}{h}\)。gradcheck 用中心差分 \(\frac{f(w+h) - f(w-h)}{2h}\) 近似。
  • 链式法则：\(\frac{\partial L}{\partial w} = \frac{\partial L}{\partial z} \cdot \frac{\partial z}{\partial w}\)；多条路径汇到同一个变量时，各路径的贡献相加（这就是 AccumulateGrad 和"梯度累加"同一个"加"字）。
  • 反向模式（reverse mode）：从一个标量输出往回走一遍，就得到对所有参数的梯度，代价约为前向的 2 倍。参数上亿、输出只有一个 loss，所以深度学习用反向模式。
  • 向量情形：反向传的是"向量 × 雅可比矩阵"（vector-Jacobian product，VJP），不会真的把雅可比矩阵建出来。

代码里才看得到的 2 件事：

  1. retain_graph=True 才能反向两次：默认反向完账本就释放了，第二次会报错。
