讲解

第一步：PP——按层切成几段，像流水线（2026-11-14）

类比：汽车装配线。 4 个工位（4 张卡），工位 1 装底盘（第 1–8 层），工位 2 装车身（第 9–16 层）……一辆车要依次经过 4 个工位。

把模型按层切成 p 段，每段放一张卡；第 i 段算完把激活用 send 发给第 i + 1 段（点对点，第 17 章）。每卡只存 \(\frac{1}{p}\) 的层，参数、梯度、优化器状态都省了。

问题：气泡。 只有一个 batch 时，工位 1 干完就闲着，等工位 4 做完前向、反向再一路传回来。用 \(t_f\)、\(t_b\) 表示一段的前向、反向时间，空等的时间占比（Playbook 第 1659 行）：

\[r_{\text{bubble}} = \frac{(p-1)(t_f + t_b)}{t_f + t_b} = p - 1\]

4 段时空等的时间是有效时间的 3 倍——绝大部分时间在等。

一句话：PP 按层切、段间传激活；只送一个 batch 时大部分时间在空等（气泡）。

第二步：micro-batch 和 1F1B（2026-11-14）

办法：把一个 batch 切成 m 个 micro-batch（小批），一个接一个送进流水线。工位 1 做完第 1 个小批，马上做第 2 个，不再干等。气泡还是那么长，但有效工作变成 m 倍（Playbook 第 1693 行）：

\[r_{\text{bubble}} = \frac{p - 1}{m}\]

数字演示：p = 4、m = 8：气泡占比 \(\frac{3}{8} = 37.5\%\)；m = 32：\(\frac{3}{32} ≈ 9\%\)。

AFAB vs 1F1B：

  • AFAB（All Forward All Backward：全部前向再全部反向）：m 个小批的激活要同时存着，显存随 m 增长；
  • 1F1B：流水线填满后，每卡做一次前向、紧接着做一次反向，做完反向就能扔掉那个小批的激活。同时存的激活只有约 p 份，与 m 无关。气泡大小不变（Playbook 第 1718 行）。

更进一步：interleaved（交错） 每卡放几小段不相邻的层，气泡再除以段数；Zero Bubble / DualPipe（DeepSeek-V3 用）把反向拆成"对输入求梯度"和"对权重求梯度"两部分来填气泡（Playbook 第 1830 行）。

PyTorch：torch.distributed.pipelining 提供 pipeline() / PipelineStage 切模型，ScheduleGPipe（≈ AFAB）、Schedule1F1B、ScheduleInterleaved1F1B、ScheduleInterleavedZeroBubble 等调度。

一句话：切成 m 个小批，气泡占比 (p − 1) / m；1F1B 让激活显存不随 m 涨；交错、Zero Bubble 进一步压气泡。

第三步：CP——序列太长就按序列切（2026-11-14）

128k 长度的序列，单卡连一层的激活都放不下。CP 把序列切成 N 段，每卡一段 token：

  • LayerNorm、MLP 是每个 token 独立算的，各卡各算；
  • attention 要看所有 token：每卡的 Q 要和所有卡的 K、V 算。

Ring Attention（Playbook 第 1467 行）：N 张卡围成环，每卡先用自己的 K、V 算一部分 attention，同时把 K、V 发给右边、从左边收下一块；N 轮后每卡的 Q 见过了所有 K、V。拼部分结果用的就是 online softmax（第 13 章 logsumexp 的流式版）。通信和计算重叠。

因果 mask 下，后面的 token 要看的多、前面的少，按顺序切会负载不均，所以用 zig-zag（之字形） 切法：每卡拿一段靠前的加一段靠后的（Playbook 第 1514 行）。

PyTorch：torch.distributed.tensor.experimental.context_parallel（实验性，接口可能改）。

一句话：CP 按序列切，attention 用 Ring Attention 一圈圈传 K、V；因果时用 zig-zag 平衡负载。

第四步：EP——专家分到不同卡，all_to_all 换 token（2026-11-14）

MoE 层有很多个专家（比如 64 个 FFN），每个 token 只去 topk 个（第 12 章）。EP：64 个专家分到 8 张卡，每卡 8 个。

一次 MoE 层：

  1. 路由：每个 token 选好去哪几个专家；
  2. all_to_all（分发）：每卡把"要去别的卡上专家"的 token 发过去（第 17 章）；
  3. 各卡用自己的专家算；
  4. all_to_all（收回）：结果发回 token 原来所在的卡，按权重合并（第 12 章 index_add）。

PyTorch 没有一键 EP 的 API，常用 DTensor + 手写 all_to_all，torchtitan 有参考实现；DeepSeek 开源的 DeepEP 是专门优化过的 all_to_all 库。

一句话：EP 把专家分到不同卡，MoE 层前后各一次 all_to_all 把 token 送去、把结果收回。

第五步：五维并行怎么组合（2026-11-14）

维度 切什么 通信频率 / 位置 放在哪
TP（+SP） 每层的矩阵 每层多次，在关键路径上 机内（NVLink）
CP 序列 每层 attention 机内或相邻机器
EP MoE 专家 每个 MoE 层两次 all_to_all 机内优先
PP 层 每个 micro-batch 一次点对点 跨机（流量小）
DP / FSDP 数据（+ 分片） 每步一次，能和计算重叠 最外层

Playbook 的三步法（第 2122–2198 行）：

  1. 先装得下：单卡放不下模型 → 先 FSDP；还不够，机内加 TP；层太多，跨机加 PP；序列太长加 CP；
  2. 再凑够全局 batch：剩下的卡做 DP，不够再用梯度累积；
  3. 最后调吞吐：在可行组合里实测，挑 MFU 最高的（第 23 章）。

PyTorch 原生的组合范例是 torchtitan：用一个多维 DeviceMesh（如 ("pp", "dp_shard", "cp", "tp")），PP 用 pipelining，FSDP2 + TP + CP 都基于 DTensor 叠在一起。

一句话：通信最频繁的放最里面（TP 机内），最稀疏的放最外面（DP / PP 跨机）；先装得下、再凑 batch、最后调吞吐。

口诀

按层切成流水线，段间传激活；一个 batch 气泡大，p − 1 倍在空等；
切成 m 个小批，气泡降到 (p − 1) / m；1F1B 前反交替，激活不随 m 涨；
序列太长 CP 绕圈传 KV，专家分卡 all_to_all；最勤的通信放机内，最疏的放外层。

数学原理

  • 气泡占比：\(r = \frac{p-1}{m}\)；流水线效率 \(\frac{m}{m + p - 1}\)。
  • 1F1B 的激活：同时在途的 micro-batch 数 ≤ p（第一段最多），而 AFAB 是 m。
  • 卡数分解：总卡数 \(= DP \times TP \times PP \times CP\)（EP 通常复用 DP 或 TP 维度）。
